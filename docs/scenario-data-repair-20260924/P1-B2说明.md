# P1-B2：保留剧本产量、分清产量与课额

工作树 `codex/p1b2-production`，基线 `c9ad8e6f`。本轮只在本工作树改动，修复保留未提交；各 rebuild 仅末尾追加步骤。原文、逐字段变更、开局探针与重建哈希均随本目录保存。

## 问题与实际消费路径

`web/tm-fiscal-engine.js` 的 `_settleLandFlow` 原先在首次结算令 B2 建筑增量为零，随后直接以人口系数覆盖盐、矿、马、渔、海贸；B3a 每次将皇庄改为耕地的 5%。天启原盐产 46.5 亿斤在开局已变成约 1176 万斤。B1 的商贸已保留首次超出自然基数的部分，B2 未跟进。

但“盐产被覆盖”与“盐税暴涨”并非同一条消费路径。对真实开局的税目取数核验如下：

| 字段 | 数据/编辑器单位 | 真正消费 |
| --- | --- | --- |
| `saltProduction` | 斤/年，不能填引数、银两或贯 | B2、营造、方志及区划面板；当前三部玩家税表均未以此字段直接征盐课 |
| `saltOutput` | 晚唐原作未写清量纲 | 河朔等势力税目 `base` 按名字读取；唐廷盐课读四种独立财政课额；不可擅自视为 `saltProduction` 别名 |
| `mineralProduction` | 计价矿产；编辑器固定写“两/年”，宋唐计价应随剧本为贯 | B2、营造、`tm-armory.js` 原料产出；通用 `mining` 税基可读取。三部现行玩家税表分别未单列、读商贸额、读 `miningFiscalAssessment` |
| `horseProduction` | 匹/年 | B2、营造、军备马政；不能把马匹库存或买马支出当成年产或现金收入 |
| `fishingProduction` | 计价渔产/年 | B2、营造、展示；三部当前未单列以此为基数的渔课 |
| `maritimeTradeVolume` | 本位钱计价海贸活动量/年 | B2、营造、海寇劫掠；现行三部市舶分别读平摊人口的固定税额、商贸总额、独立舶货财政课额 |
| `imperialFarmland` | 亩 | B3a；通用 `imperial` 税基与展示。三部未单列该田亩的直接租税；内帑其它固定来源不能冒充本字段所生收入 |

天启还有一处独立现象：JSON 的旧式 `fiscalConfig.taxes` 写了人口 × 0.04 的盐课，但初始化将旧数组转为税种开关，真实征收回落 `DEFAULT_TAXES`，按人口 × 0.2 计盐铁。本轮探针记录真实执行的 `base`，不按 JSON 的旧说明猜收入。

## 引擎改法与兼容

新增内部函数 `settleProductionBase`，B2 五项与 B3a 共用：

1. 首次以已存在的剧本量为自然基数，记下单位人口/田亩的自然率；明确的 0、低于人口兜底的量和小数也保留。仅仿照 B1 取 `max(剧本值, 人口公式)` 仍会吞掉低产量和零，故这里校准自然率。
2. 后续自然量随人口或耕地增减；当前产量超出上次自然量的差额按 B1 规则保留为营造增量。驱动量不变时保留上次自然量，避免小数反复取整漂移。
3. 旧存档已有 `_<字段>NaturalLast`、没有新增自然率时，继续用原人口系数与已有差额，不将已建增量重新识别为自然产量。原 B2 的 `_pBuilt` 是局部计算值，不是独立存档字段。
4. 新增状态为 `NaturalRate`、`NaturalDriverLast`；JSON 存读档可保留。旧档已被旧引擎抹掉的原始剧本值无法从差额反推，本轮不从新剧本强行回灌旧世界。
5. 无相应产区标签时仍保留原有不浮动语义；字段缺席时仍使用原 `_ensureEconomyBase` 兜底。

回归 `web/scripts/smoke-production-authored.js` 覆盖六字段的首回合高值/低值/零、人口与田亩增减、营造差额、旧状态迁移、新档往返、非产区与小数稳定性。原 `smoke-production-b2.js`、`smoke-commerce-float.js` 继续校验缺字段的原兜底与 B1。

## 数据规则及史料边界

补丁 `patches/p1b2-production.js` 读取后先核验 `JSON.stringify(scenario)+'\n' === raw`，支持只报告、`--report`、`--write`；三个数据模块为 `data/{tianqi,shaosong,tang}-production.js`。原文摘录集中在 `data/p1b2-sources.js`，运行补丁时逐条对本地 wikitext 作包含校验。每个原文章节配有来源 URL、修订号和时间的 JSON。

- **天启**：按《明史》卷八十的万历额盐及“凡大引四百斤，小引二百斤”换算。有“余”的数取明载整数下限。广东与海北由 `(30200+34600+12400)×200` 得 1544 万斤，替换原 4 亿斤。两浙、云南此前保留了错误的省级零总数，这次补入有明文的额盐与产区标签。府内分布沿用已有权重，或依分司数分摊，是模型分布，不冒充史载府额。见 [天启逐字段报告](reports/p1b2-tianqi.md)。
- **绍宋**：按《宋史》卷一百八十二、一百八十三所列淮南、两浙、福建、两广旧额落到对应产区，以所载“**五十斤為石，六石為袋**”统一盐斤口径。它是开局参考旧额，不是建炎元年现场统计；天圣以后的额数升降与跨期石制仍需进一步细核。见 [绍宋逐字段报告](reports/p1b2-shaosong.md)。
- **晚唐**：原文给的是财政课利，不能搬成盐斤。《唐会要》卷八十八太和三年：“**安邑解縣兩池榷課。以實錢一百萬貫為定額。**”《新唐书》卷五十四另有李巽时期两池一百五十余万缗，不是同一年的同一账。既有独立盐课、茶课、舶货课额保留。坑冶用“**舉天下不過七萬餘緡**”取七万下限，除以通用引擎既有 10% 计量尺，形成 70 万贯的**模型计价产值**，按原坑冶课额的 13 州分配；10% 不是考定的唐代法定税率，也不是现行唐剧本的课额税率。其它州此项分配为零以免再叠人口兜底，不等于断言没有采矿。见 [晚唐逐字段报告](reports/p1b2-tang.md)。

下列数没有获得足够原文支持，保留现值并在数据模块报告中逐项记疑，不制造一套假精确的新数：

- 天启矿、渔、海贸毛产值与全国皇庄田；《明史》矿税“二十五年至三十三年……幾及三百萬兩”是九年累计，且混有强征，不能定作1627年矿产。弘治畿内皇庄与天启全国皇产、王庄也不是同一口径。
- 天启陕西马额与六茶司“九千六百匹”加天启“二千四百匹”同数，但**易马是购入流量，不是繁殖产量**，未叠加一遍。
- 绍宋未列盐区及矿、马、渔、皇庄的原公式估数；川盐财政课有钱、银、绢，不能直接当斤数。元丰川茶百万元与全宋茶课范围不同。市舶二百万缗参照包含“抽解與和買”，不能全当作税收再倒造海贸额。
- 晚唐 `saltOutput` 的原单位，以及马、渔、海贸等物产总量。没有可靠换算时保持字段独立。

## 开局收入对比与量级核验

探针 `tools/p1b2-probe.js` 复用 `loadGame`，真实执行 `doActualStart`，然后 `CascadeTax.collect({force:true,turnDays:360})`。观察钩子仅插入 VM，不修改税额计算；原版引擎和数据从 `git show c9ad8e6f` 读入内存，不复制大剧本。固定开局随机序列，所有网络为本地桩，未调用真实模型。

这是与原有 `fiscal-probe.js` 相同的 **360 天财政年度口径**，不是带 AI、人口、战争、支出的完整游戏一年。旧财政分母为365，唐账本为360，二者差异在报告明示。`central` 为中央实际入库，`local` 为地方实际留用；史料的岁课或榷利不能只与中央一列混比。

收入、产量与哈希的最终对比由 [对比报告](reports/p1b2-comparison.md) 汇总；底稿为 `reports/p1b2-{before,after}-{tianqi,shaosong,tang}.json`。

当前税表不直接读 B2 的盐斤、马匹等字段，因此保留与规整这些物产本身不应改变原有税收。财政稳定必须由前后探针验证，不能把“收入不变”写成“产量仍被覆盖”。营造、原料、马政与显示仍实际读取这几项。

## 待拍板

若要使所有官方盐课、坑冶和市舶收入直接跟随这些产量，需要另定各朝税基与价率、专卖工本、和买、起运/留用，及未登记产业的估算规则。现有税基有上述脱节，但原文不支持把每斤盐或每匹马一律当作一单位钱。本轮保留当前税表；产量修复与上述税制选择均已形成可核对的材料。

合入时底已是 `bedc3208`（晚唐第十二至十四刀），`rebuild-tang.js` 里本补丁排在承载力之后。审查改了补丁四处，以上 MD5 与范围凭证因此是旧底旧稿的数：
