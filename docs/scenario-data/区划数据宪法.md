# 区划数据宪法（官方剧本 · 2026-09-24 立）

这份文档规定官方剧本里「势力 › 省道 › 府州」三级区划数据该写什么、怎么写。字段口径以运行时实际读取为准（方志 `phase8-formal-map-dossier.js` 的 `regionBundle`、财政 `tm-fiscal-engine.js`、民心 `tm-minxin-hard-links.js`、户口 `tm-huji-engine.js`、开局 `tm-endturn-province.js` 等），不以预览页或草稿为准。

守卫：`web/scripts/lint-scenario-data.js`（棘轮，挂在 `lint-arch-all`）。问题数只许减不许增，修完一刀用 `--update` 收紧基线。

---

## 一、总则

1. **真源唯一**：官方剧本只改仓根 `scenarios/*（官方）.json`，派生物一律用 `node web/scripts/sync-official-scenarios.js` 重生成。改动用可重跑的补丁脚本做，每次附字段级变更清单。
2. **编辑器是宪法，游戏是演绎**：剧本只写开局事实与规则。数字是开局种子，开局后由引擎演变；叙事字段写史实与处境，不预写结局。
3. **不写没人读的字段**：剧本里的每个字段都必须有游戏或编辑器代码读取。制作说明、来源备注、生成标记（`_note`、`_codexGenerated`、`mapSourceIds` 之类）不进真源，写到 `docs/` 下的旁注里。
4. **省道记叙事，府州记账**：省道节点放长官与叙事；所有户口、钱粮、兵数都记在府州叶子上，省道上看到的数一律由下辖府州实时汇总。为兼容旧读取点保留在省道节点上的数，必须恰好等于下辖府州之和。
5. **不发明数据**：没有依据的数不硬造；可以按史料估，但要在旁注里写明依据与可信程度。拆分地块不复制军队、钱粮和人物。

## 二、三级结构

| 层级 | 在数据里是什么 | 在地图上是什么 |
| --- | --- | --- |
| 天下（势力） | `adminHierarchy` 的一棵树；键名是 `player`（玩家势力）或该势力的 `id` | 同一势力所有地块合成的疆域 |
| 省道 | 树的一级节点（明为布政司/都司，宋为路，唐为道/方镇） | `map.circuitRegistry` 的一组，`memberRegionIds` 列出下辖地块 |
| 府州 | 树的叶子节点 | `map.regions` 的一个地块；叶子用 `mapRegionId` 绑定 |

- 树上必须写 `factionId` 与 `factionName`，都要和 `factions` 表里那一个势力一致。引擎开局按树的键名找势力，键名对不上会整棵树跳过。
- 一个地块只属于一个省道；地块的 `parentId`/`circuitId` 指向所属省道。
- 不绑地块的原账（流动人群、山寨、海商网络）允许存在，叶子的 `mapRegionId` 指向其上级区划，守卫单列为「非领土账」。

## 三、省道节点

| 字段 | 必备 | 类型与写法 |
| --- | --- | --- |
| `id`、`name` | 是 | id 全剧本唯一 |
| `level` | 是 | `'province'` |
| `officialPosition` | 是 | 长官官称，如「顺天巡抚」「淮南节度使」「京畿路安抚使」 |
| `governor` | 有则写 | 长官人名，必须在人物表里；考不出就不写，界面显示「任官未详」 |
| `description` | 是 | 两到四句，写本道地理、要害、时势 |
| `strategicValue` | 宜写 | 一两句：本道在全局中的分量 |
| `threats` | 宜写 | 数组：眼下的外患内忧 |
| `leadingGentry`、`academies`、`tradeRoutes`、`religiousSites`、`recentDisasters` | 宜写 | 数组 |
| `specialCulture` | 可选 | 一句风俗 |
| `capitalChildId` | 宜写 | 治所所在府州的 id |
| `children` | 是 | 下辖府州 |

省道节点不另记户口、钱粮、兵数。为兼容保留的 `population`、`populationDetail`、`fiscalDetail`、`economyBase` 等必须等于下辖府州之和。

## 四、府州叶子

### 4.1 身份与官守

| 字段 | 必备 | 写法 |
| --- | --- | --- |
| `id`、`name` | 是 | id 全剧本唯一；名字在同一剧本内不与别的地块重名 |
| `level` | 是 | `'prefecture'` |
| `divisionType` | 是 | 府、州、军、监、县、镇、卫、所、司、部、国等本朝实有称谓 |
| `officialPosition` | 是 | 本级长官官称：知府、知州、府尹、知军、宣慰使……藩属与部族写其本称 |
| `governor` | 有则写 | 人名，必须在人物表里；考不出不写，界面显示「任官未详」而不是出缺 |
| `capital` | 是 | 是否本道治所 |
| `mapRegionId` | 是 | 绑定的地块 id |
| `parentDivisionId` | 宜写 | 所属省道 id |
| `regionType` | 是 | 直辖、羁縻、土司、藩属、军镇等（引擎按它分辖治方式） |
| `dejureOwner` | 是 | 法理归属势力名（全小写 j，不要另写 `deJureOwner`） |

### 4.2 地理与物产

| 字段 | 写法 |
| --- | --- |
| `description` | 一到三句，只写本府州：山川形胜、城市、物产、人事、时势。不写「地块」「剧本」「绑定」「数据」这类制作或游戏用语，不同府州不共用同一段 |
| `terrain` | 中文：平原、丘陵、山地、高原、草原、荒漠、沼泽、森林、水网、海岛，可用「·」并列两种 |
| `specialResources` | 中文，「·」分隔，只写本府州实有的 |
| `tags` | `{hasPort, saltRegion, mineralRegion, horseRegion, fishingRegion, imperialDomain}`，按本府州实情逐项判定，不照抄上级 |
| `taxLevel` | 轻、中、重 |

### 4.3 户口

| 字段 | 写法 |
| --- | --- |
| `population` | **数字**，等于 `populationDetail.mouths` |
| `populationDetail` | `{mouths, households, ding, fugitives, hiddenCount}`；户均口数 2～12，丁、户都不多于口 |
| `byGender` | `{male, female, sexRatio}`，都是数 |
| `byAge` | `{young, ding, old}`，每项 `{count, ratio}` |
| `byEthnicity`、`byFaith` | `{名称: 0～1 的占比}`，加起来约等于 1；不用 `"34%"` 字符串 |
| `bySettlement` | `{fang, shi, zhen, cun}`，每项 `{mouths, households}` |
| `baojia` | 可选：`{baoCount, jiaCount, paiCount, registerAccuracy}` |
| `carryingCapacity` | 对象：`{arable, water, climate, historicalCap, currentLoad, carryingRegime}` |

### 4.4 民情与吏治

`minxin`/`minxinLocal`、`corruption`/`corruptionLocal`、`prosperity`、`unrest` 都是 0～100 的数。开局两对值相同。按本府州实情定，不整省照抄。

### 4.5 财赋与经济

| 字段 | 写法 |
| --- | --- |
| `fiscalDetail` | 开局账：`{claimedRevenue, actualRevenue, remittedToCenter, retainedBudget, compliance, skimmingRate, autonomyLevel}`；三个率都是 0～1；实征不大于应征。`fiscal` 是引擎开局从它复制出来的活账，剧本不必写 |
| `publicTreasuryInit` | `{money, grain, cloth}` |
| `economyBase` | `farmland`（亩，是整数量级，不是比例）、`commerceCoefficient`、`commerceVolume`、`maritimeTradeVolume`、`saltProduction`、`mineralProduction`、`horseProduction`、`fishingProduction`、`imperialFarmland`、`imperialAssets{zhizao,kuangchang,yuyao}`、`postRelays`、`kejuQuota`、`roadQuality`、`landsAnnexed`、`landsReclaimed`、`landsSurveyed`、`disasterRecord` |

单位：钱用本剧本的货币单位（明为两，唐宋为贯），粮为石，帛为匹，田为亩。

## 五、可选扩展账本

以下账本由剧本声明启用，引擎有专门读取；目前只有晚唐声明。它们合法，但须成组声明、口径一致，不许只写一半。

| 扩展 | 声明处 | 叶子上的字段 |
| --- | --- | --- |
| 户口账 `tm-population-ledger/2` | `populationConfig` | `populationDetail` 增加 `registeredMouths`、`registeredHouseholds`、`taxableMouths`、`taxableHouseholds`、`registeredDing`、`hiddenDing`、`fledDing`、`exemptDing`、`baselineExemptDing`、`mouthsPerDing`、`registeredLand`；`demographicAccounting` |
| 财政账 `tm-fiscal-ledger/2` | `fiscalConfig.accounting` | `fiscalDetail` 增加 `accounting`、`period`、`isForecast`、`resources`、`taxOverrides`、`collection`、`logisticsLoss`、`collectedRevenue`、`skimmed`、`lostInTransit` |
| 公帑 `tm-public-treasury/2` | `publicTreasuryConfig` | `treasuryBinding` |
| 人力 | 剧本内 `renliSeed` 成组出现 | `renliSeed` |
| 地方阶层处境 | 阶层表有对应 `classId` | `socialConditions` |
| 边警 | — | `securityContext`、`governanceMilitary` |

扩展账本之外再新造字段，必须同时提交读取它的引擎或界面代码，并在本文件登记。

## 六、人物、势力与其他引用

- 实体（人物、势力、党派、阶层、军队）都要有 `id` 与 `sid`，id 全剧本唯一。人物 id 重复会在开局去重时丢人。
- 人物 `faction` 写势力名、`factionId` 写势力 id，二者指同一个势力。
- 人物的 `party`、`class` 写党派表、阶层表里的全名或 id，不写简称。
- 官职任职者、统兵官、党魁、势力首领写人物表里的名字。多人分统、泛指（「各土司首领」）写进说明字段，不写进人名字段。
- 名字用本名；封号、谥号、庙号写在 `title`、`zi`、`haoName` 等字段。
- 史实人物优先。虚构人物只在确有戏份时设立，不批量起名，不同一人挂到多个地方。

## 七、守卫规则一览

规则全文见 `web/scripts/lint-scenario-data.js` 的 `RULES` 表，分六类：

- **引用**（`ref.*`）：人物、势力、地块、行政树、省道、官制、军队、党派、阶层、关系之间互相指得上。
- **格式**（`fmt.*`）：人口是数字，结构占比是数，地形是中文，省道登记有 `memberRegionIds`。
- **数值**（`num.*`）：户、丁不多于口，户均口数 2～12，0～100 与 0～1 的量不越界，实征不大于应征，耕地量纲对。
- **文字**（`text.*`）：地方描述不写制作过程和游戏术语，同一段不用于三个以上区划。
- **府州**（`leaf.*`）：不整份照抄上级的定性字段，同一上级下不出现三个以上人口相同的府州。
- **死字段**（`field.dead`）：剧本里有、游戏与编辑器脚本一处都不读的字段，按出现次数计。

新增规则或修完一刀后，跑 `node scripts/lint-scenario-data.js --update` 收紧基线，并在提交说明里写清哪条规则降了多少。
