## 发现并修正的失败

- 初期补交材料后直接开始工作：改成新任务版本实际递送，协助者重新决定；保留正确行为断言。
- 初期浏览器点击被既有首次指引遮挡：测试通过真实按钮关闭，未绕过命中检查。表达式包装语法错误也已修正。
- 初期保存断言假定只有两项计划：改为保存前后每项 ID/阶段/消息数完全相同；另修了刚结束来往后立即补空泛问候的刷屏，并保留数量断言。
- 首次全量暴露无 HTML 解析测试桩下空节点绑定：生产渲染器只对存在的节点绑定，领域仍正常运行。相关七个官方开局/省道测试重新通过。
- 新增三脚本使启动精确计数失配：明确列出三个新增模块及加载顺序，仍要求全部旧脚本精确保留。
- 改代码后原生准备清单过期：用原生成器重新生成；没有放宽字节契约。
- 首次全量的开局完整性超过 120 秒，完整过回合中的开局 VM 也触及内部 10 秒限时：将首次进入限制为 4 次决定，并跳过空待办事务，保留正常事件 48 次预算。第二次全量仍触及开局 VM 限时，遂将初始计算排到初始化返回后的事件循环，捕获世界租约，未增加预算或游戏时间。原期限/夹具不改，重新运行全量验证。
- 两个新回归在模拟失败事务后继续断言旧对象引用：按既有回滚契约重新读取当前世界对象，同时验证旧对象票据失效。
- 原开局深度核读的取消测试出现第二个请求：调用栈和请求正文确认来自原人物情节弧计时器，未改深度核读重试策略。给该既有计时器和结果加世界租约，并沿现有 signal 取消；精确原测试重新通过。生命周期文件另有正常规划的模型替身正向测试，这一组不作为零 API 证明。
- 新玩家票据在世界忙碌时仍能提交：真实模块夹具复现后加同步提交门槛，忙碌时无消息、无预算消耗，恢复后可重试。原生开局在保存提交完成后再唤醒初始化，避免忙碌阶段跳过后遗漏。
- 最终预检仍有一次开局总耗时超过 120 秒：首次进入新增的普通联系限 1 项，明确目标和待办保留，避免初始化内多次无目标发起及其世界快照。固定开局测试随后为 76.7 秒，原期限未改；普通通问完整回复的正向回归保留。
- 后续整套慢运行仍触及该门槛：生产剖面显示 NPC 两步提交/递送的完整世界快照占主要新增成本。把本地同地发送与实际送达合入原行动的同一次短事务，新增接收写失败回滚/重试/独立回应断言，独占开局回归 93 秒通过。测试并发时的超时也保留，未改原时限。
- 粗粒度 30 日回合下，已经接受的短工作现在先获得办理机会；答复期限不倒改为已完成工作的失效期。明确延期带来新期限，未收到消息时发起人仍只看旧期限；延期到上限不转换成玩家拒绝。

## 浏览器证明的边界

生产 Electron 33.4.11 / Chromium 130；实际 index、main、preload、书信页面及保存 IPC。只给初始三名无官人物、地点、关系和一个引见目标，不预置 plan/message/accepted/done。用真实 DOM 控件并检查可见命中，不是操作系统鼠标测试。保存使用临时 userData，不读取玩家存档。

所有模型入口的尝试数必须为 0，即使异常被捕获也使测试失败。没有使用“固定返回值的模型”证明零调用。网络拦截是第二层证明。官方初始化其它阶段和未接管自由推演不在本轮零 API 声明内。

未验：真实付费模型、手机实机、玩家生产存档、三官方剧本逐一人工完整游玩。三官方源/派生一致与原有皇帝/领域路径由现有回归覆盖。公开与私人信息测试限于本轮新活动及其模型投影，不宣称全游戏已限知。
