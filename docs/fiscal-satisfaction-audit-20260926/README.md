# 财政右栏与阶层、党派数值审计

日期：2026-09-26。结论来自当前本地源码与根目录官方天启 JSON 的离线复现。本次只调查，新增本目录的探针、结果和报告；未修改生产代码或玩家存档，未调用真实模型，未提交、推送、打包或发布。

## 结论

1. **财政收入虚高有确定的代码缺陷。** 民心财政联动把无回合周期的地方收入估算覆盖到本期/月收入；真实财政流水和余额没有增加。右栏又直接读取被覆盖的字段，因此会显示巨额收入和虚假结余。
2. **阶层满意度普遍快速下跌可在不加入玩家操作或 AI 回包时复现。** 主要问题是欠饷、地方风险的关键词匹配扩散到全部阶层，多个压力叠加快速耗尽每回合 14 点预算；该预算又将正向恢复一起挡住。
3. **党派凝聚力有独立的小数截断 bug。** 每次接收阶层变化前，旧凝聚力被截为整数，导致额外扣减、回升丢失，且近账增减之和与实际变化不符。

不能据此把玩家这局的全部下降逐项归因：没有玩家存档、完整操作记录或模型回包。现有证据已经足以说明，不能将反馈简单归咎于玩家操作。

## 1. 财政：估算覆盖实际流水摘要

### 根因路径

- `web/tm-minxin-hard-links.js:207` 取 `fiscalDetail.claimedRevenue`，缺失时用人口乘系数；`244-246` 计算实际/上解估算，`303-310` 汇总。该链路没有将收入换算为当前回合天数。
- `web/tm-minxin-hard-link-consumers.js:106` 只有统一财政分支使用权威账本。当前天启不走这一分支，`124-131` 将上述估算同时写入 `guoku.turnIncome`、`guoku.monthlyIncome`，不更新入库流水或库存。
- `web/tm-endturn-core.js:252` 的提交前流程调用了这条路径，缺陷存在真实入口。
- `web/phase8-formal-rightrail.js:1486` 优先读这个 `turnIncome`，`1488` 用它减支出计算结余；分项却在 `1430` 起读取真实 ledger，所以总额与分项可能相互矛盾。

### 正式开局隔离复现

同一 VM、同一时点，仅执行民心财政消费者：

| 字段 | 调用前 | 调用后 |
|---|---:|---:|
| 本期实际入账 `ledger.thisTurnIn` | 425,836 | 425,836 |
| 显示用 `turnIncome` | 425,836 | 49,598,642 |
| 国库余额 | 26,370.1848 | 26,370.1848 |
| 右栏收入 | 42.6 万 | 4959.9 万 |
| 右栏结余 | -82.4 万 | +4834.9 万 |

后续两次隔离运行同样产生超过十倍的显示/实账分叉。主探针 10 项断言通过，包含真实库存/流水未变与运行前后生产输入 SHA-256 一致。

据奏失真默认关闭且幅度封顶 35%，不能解释此数量级；关闭后缺陷仍可复现。精确重现玩家的 1746.3 万需要原存档。

**修复方向：**阻止民心估算覆盖已结算收支，让联动影响税收输入并通过财政引擎结算；右栏与详情统一使用带实际/预计、周期标识的权威报表。只改显示会让其他读取 `monthlyIncome` 的系统继续收到错误数值；也不能对所有自定义剧本一律除以 12。

证据：[主探针](fiscal-probe.cjs)、[主结果](fiscal-results.json)、[独立交叉核查](fiscal-crosscheck.md)。

## 2. 阶层：压力扩散与恢复额度问题

### 已证实的目标误匹配

`web/tm-party-class-ecology.js:115` 将“饷”同时列入税负类别；`399-412` 又把土地/税负关联相通。`web/tm-social-political-signals.js:1081-1095` 只要得分大于 0，就给予整额影响，不按匹配强度缩放。

最小对照只设置欠饷压力，使用相同的天启九阶层：

- 原始生态匹配：欠饷信号命中全部九阶层，各请求扣 5 点，宗室、商人、僧道同样中招。
- 仅在 VM 关闭生态扩展：欠饷只命中军户。

地方风险匹配也因“地方”中的“地”扩散至土地类别。正常持续欠饷、腐败造成持续负面影响可以是机制；这类无身份、地域区分的整额扩散是本次发现的问题，不能混作“玩家操作差”。

### 官方开局压力链的数值

固定非社会状态，不加玩家操作，不使用 AI 结果，每轮运行真实调度器及 SocialFoundation：

| 满意度 | 初始 | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---:|---:|---:|---:|
| 宗室 | 62 | 48.9 | 36 | 22.9 |
| 士大夫 | 30 | 16.9 | 3.8 | 0.9 |
| 商人 | 50 | 36.9 | 23.8 | 10.7 |

第 5 次后九阶层均为 0.9。对照组仅运行结构回归时，士大夫反而逐步回升；所以本次急跌主要来自压力信号和行动叠加，不是结构回归本身。

例如商人第一轮收到腐败 -6、欠饷 -5、地方风险请求 -8（额度只放行 -3），合计 -14，结构回归再补 +0.9，净 -13.1。

### 正向恢复被挡住

`web/tm-class-engine.js:811` 将规则说明为每回合“净变动”限制，但 `827-833` 用绝对变动总和消耗预算。最小复现：满意度 50 → 批准 -14 后为 36 → 同回合再请求 +10，实际批准 0，仍为 36。发生压力扣减后，惠政恢复可能被无声吞掉。

这不是加减号笔误：现有单元测试主动验证了正负共用额度。问题是该设计与提交前先扣压力、后接收玩家措施的调用顺序组合后，阻断了恢复通道；修复需要明确机制含义并更新相应测试。

**修复方向：**按真实受影响身份/地域选择目标，修正多义单字匹配；将压力强度与匹配强度分开；明确每回合净变化或正负分开额度，保留恢复通道。持续压力频率与幅度另作平衡验证，不能用全局调低一个系数掩盖错误目标。

证据：[阶层完整报告](class/REPORT.md)、[阶层探针](class/probe-class.cjs)、[多轮结果](class/class-results.json)、[关键词最小对照](class/probe-semantic.cjs)、[对照结果](class/semantic-results.json)。

## 3. 党派：逐笔截断造成额外扣分

党派现行链路主要处理凝聚力/影响力。天启还保留旧 `party.satisfaction`，但本次实验中该字段一直不变。因此不能将玩家所说的“党派满意度”直接等同于它。

`web/tm-class-engine.js:475` 使用 `parseTurnNumber(ps.cohesion)` 读取旧凝聚力，而该 helper 在 `212-215` 使用 `parseInt`。阶层传导却允许小数，默认亲和度为 0.5。

| 东林起始凝聚力 82 | 应有结果 | 实际结果 |
|---|---:|---:|
| 两笔各 -0.5 | 81 | 80.5 |
| 两笔各 +0.5 | 83 | 82.5 |

仅在 VM 把读取方式换为浮点值，两方向结果都恢复准确。压力单独运行第一轮，东林近账传导合计 -14，实际却从 82 降到 66.5，多扣 1.5。

本次完整社会隔离组第六次东林凝聚力 82 → 23.55，浙党 55 → 0，但阉党 65 → 74.9。复现的是部分党派因阶层传导快速下滑，不能据此声称所有党派数值都会下降。

另外，合成校准结果可通过绝对 `cohesion:0` 或同批重复五条 `cohesionDelta:-15` 将 65 直接降至 0。它是另一个已复现的写入限制缺口；没有真实回包，不能确定玩家触发过。

**修复方向：**保留凝聚力小数和合法零值，近账记录实际增减；校准器将绝对更新转为受限增量，并按党派合并同批重复更新。

证据：[党派报告](party/README.md)、[最小探针](party/probe.cjs)、[结果](party/probe-results.json)。
