## 一、总纲

一句话：天命从「经营一个国家」转向「过一个人的一生、撑起一个家」。你是谁，决定了你面前有什么事、你能用什么手段、你看得见什么、谁能拿你怎么样。

### 1.1 与 CK3 的根本差别

| | CK3 | 天命 |
|---|---|---|
| 权力从哪来 | 地：头衔等于领地、封臣、兵和税 | 职与身份：官职是权与责；不当官的人靠功名、门第、财力、人脉 |
| 传给下一代的 | 头衔 | 家：门第、荫、家产（诸子均分）、世交、声名；官职不传 |
| 日常在做什么 | 管封臣、打仗、谋划 | 办事：处置案头的公事、乡事、家事 |
| 议事会职务 | 派一个任务，按技能自动推进 | 没有自动推进：每件事的结果都是有人做了选择 |

### 1.2 三条贯穿全稿的原则

1. **履职是行动，不是分数。** 官员的政绩等于他办过的每件事的总和，不再有一个向能力靠拢的履职度。
2. **能力决定你能办几件、看清几分、有哪些招，不决定结果。** 结果由选择和世界的状况决定。
3. **一套事、一套分派、三种坐法。** 皇帝、官员、不当官的人面对的是同一个世界里的同一批事，只是坐在案前的位置不同：皇帝在最顶端批，官员在中间办，不当官的人在案外托、告、捐、议。

### 1.3 沿用的设计铁律

- **宪法与演绎分栏**：类型、分派、期限、账本、考核、传承规则由代码定；事的具体内容、牵涉的人、NPC 在要紧事上的抉择、各方反应由 AI 演绎。代码只产骨架、只验结果，不写剧情。
- **AI 的说法只算声明**：处置的结果只能经现有领域写口落账，有回执可核（#89、#90 已立的契约）。
- **玩家操作只走五渠道**：本稿把五渠道推广为按身份配置，不另开入口（第九章）。
- **失败禁玄幻惩罚**：后果只能是政治、社会、经济上的。
- **工具与系统不混**：查阅、筛选、提示零代价；处置、公文、私书、行止才有代价。
- **朝代中立**：代码只用抽象键；知县、布政使、票拟这些名字来自剧本的朝代包。
- **设开关必配设置项**。

## 二、三个核心概念：事、职、人

### 2.1 事

世界由事组成。每件事都有类型、地点、期限、牵涉的人，以及**实情**和**呈报**两套事实。

事分三个层面：

| 层面 | 是什么 | 例子 | 谁的案头有 |
|---|---|---|---|
| 公事 | 官府的事 | 开征、解运、奏销、命案、缺官、修城、赈灾 | 在任官员（按职权与辖区分派） |
| 乡事 | 地方社会的事，非官非私 | 义仓施粥、修桥、团练、宗族纠纷调处、士绅联名 | 有功名、门第或族长身份的人（按乡里声望分派） |
| 家事 | 一家之内的事 | 婚嫁、子弟读书应试、置产分家、丧葬丁忧、人情往来、家讼 | 每个人 |

事从五个地方来：

1. **时令**：征期、奏销、考满、京察大计、科期。
2. **账本信号**：亏空、欠饷、灾伤、缺官、民变苗头。
3. **人的行动**：告状、请托、上疏言事、弹章、捐输、包揽。
4. **上级交办**：诏令、公文下达后，变成下级案头的事，有期限、要复命。
5. **AI 生事**：AI 在推演里提出新事（某府士绅抗粮、某县出了命案、某卫哗饷），过闸才入册。

前四种由代码生骨架、AI 填血肉：代码决定「有一件什么类型的事、涉及多少银粮、限期到哪天」，AI 决定「这件事具体是谁、为什么、还牵扯到谁」。第五种由 AI 起头，但必须过**生事闸**：

- 类型必须在事类目录里；
- 数额不得超过该地账本承受得了的上下限（例如抗粮额不超过该府本期应征）；
- 利害人必须是在册活人或已有阶层，不能凭空造人；
- 事实没有账本佐证的，标「风闻」。风闻之事照样可以浮上案头，但处置里多一条「派员查实」：查实了按实情结算，查无实据就撤销；
- 每回合入册有上限〔初值 3 件〕，超出的按显著度取舍。

### 2.2 职

**职 = 权 + 责。**

- **权**：决定哪一类、哪一片地方的事送到谁的案头（分派），以及他能对这件事做什么（手段）。
- **责**：办过的事怎么记账、由谁来考、牵连到谁。

不当官的人没有职，但有**身份**：功名、门第、族长地位、财力。身份决定他能收到哪些乡事、能敲开哪些门（谒见官员、联名、优免）。

### 2.3 人

关系决定事怎么办。官场上的关系多半是制度造出来的（座主门生、同年、举主、上官属官），各带机械后果；人情和把柄是可以积累、可以兑现的筹码。

## 三、事的一生

每件事都走同一条路：

```
生 ──> 派 ──> 办 ──> 结 ──> 考 ──> 余波
│      │      │      │      │      └ 利害人反应，可能生出新事
│      │      │      │      └ 进入经手人的政绩账，供考核、弹劾、交代读取
│      │      │      └ 经现有领域写口落账，出回执
│      │      └ 链上每一站各做处置：主办、会办、核转、批准、封驳
│      └ 按职权与辖区算出主办和上呈链
└ 时令、账本信号、人的行动、上级交办、AI 演绎
```

### 3.1 事的数据形状

```js
GM.matters = {
  byId: {
    'm-1627-09-0042': {
      id, sphere: 'public' | 'local' | 'household',   // 公事 / 乡事 / 家事
      domain: 'revenue',            // 钱粮；其余见朝代包事类目录
      kind: 'collection',           // 本域内的事类，如 开征/解运/奏销/蠲缓/加派/亏空/优免诡寄
      organizationId,               // 属于哪个势力的官府（多政权各有一套）
      locus: { regionId, circuitKey, orgUnitId },     // 落在哪里
      subject: { silver, grain, ... },                // 涉及的数额或对象（宪法：有类型的数）
      facts: { actual: {...}, reported: {...} },      // 实情与呈报
      deadline: { turn, day },                        // 限期
      precedent: 'collection.routine',                // 成例：没人亲办时照此办
      stakeholders: [{ ref, interest, weight }],      // 利害人（演绎填）
      origin: { kind: 'calendar' | 'signal' | 'actor' | 'order' | 'ai', ref },
      verification: 'confirmed' | 'rumor',            // AI 生的事没有账本佐证时为「风闻」
      chain: [                                        // 分派结果与各站处置
        { positionRef, holderId, role: 'lead' | 'co' | 'review' | 'approve' | 'veto' | 'notify',
          status, disposition, turn, receiptRefs }
      ],
      status: 'open' | 'escalated' | 'settled' | 'overdue' | 'buried' | 'disputed',
      salience,                                       // 显著度（决定会不会浮上案头）
      narrative: { title, summary }                   // AI 演绎的文字，只作展示与推演上下文
    }
  },
  byDocket: { [holderKey]: [matterId, ...] },         // 案头索引
  seq
};
```

- `holderKey` 是人物 id；没有具名在任者的职位（大量州县）用职位键，走第五章的「依例」。
- 只有 `subject`、`facts`、`deadline` 这些有类型的字段会被结算读取；`narrative` 只给人看、给 AI 当上下文，结算绝不读。

### 3.2 案头的量

最大的风险是做成公文模拟器。硬规定：

- **每回合浮上玩家案头、需要玩家拍板的事，不超过 5 件〔初值〕。** 按显著度取前几件，其余到回合末自动照惯例办。
- 玩家可以主动从「待办」里把某件事拉上来亲办，但受亲办额度限制（5.3 节）。
- 显著度〔初值〕：

  ```
  显著度 = 2.0·log10(1 + 涉及银粮折银)      // 事的大小
         + 3.0·紧迫                         // 1 / 剩余回合数，过期为 1.5
         + 2.5·Σ(利害人与持有人的关系强度)     // 熟人、上官、座主来说情，显著度高
         + 3.0·失真度                        // |实情 − 呈报| / 实情，数对不上的事更显眼
         + 4.0·(上官或皇帝交办 ? 1 : 0)
         + 1.0·新异                          // 本任内同类事第一次出现
  ```

## 四、权：分派

### 4.1 职位新增四项

官职本身不带专门写给它的代码，只是一张分派表。在现有职位字段（职权 `powers`、品级、员额等，见附录）上补四项：

| 字段 | 含义 | 缺省（旧剧本不改数据也能跑） |
|---|---|---|
| `jurisdictionId` 辖区 | 管哪片地方、哪些事类；值为行政树节点 id | 地方官取其绑定的地块或省道；京官取全国，事类取其职权 |
| `reportsTo` 统属 | 向谁呈报；可写职位 id，也可写「部门/职位」路径 | 州县呈府，府呈省道主官，省道呈对口的部，部呈元首；衙门内佐贰呈堂官 |
| `authorityLimits` 权限额度 | 哪些处置可以自己定，哪些必须上呈 | 按品级与职权推（例如蠲免、死刑、动用起运银一律上呈元首） |
| `review` 考成项 | 按什么考、谁来考 | 由职权推出（征税权考钱粮完欠；刑狱权考积案冤案）；考者取有监察权、覆盖此辖区的职位 |

下属（`directs`）不另存，由 `reportsTo` 反推。

落地要点（附录 A 节）：

- 现在职位上**没有任何显式的上下级字段**，官制树装载时还会被拍平，所以统属只能靠新字段加缺省推导，不能靠部门嵌套。`reportsTo` 的解析照抄省道 `governorOffice` 现成的写法（职位 id 或「部门/职位」路径两种都认）。
- `OfficeHolderState` 和履职模块已经优先读 `jurisdictionId`，名字就用它。晚唐职位上的 `regionId` 是「治所州」的意思，不能直接当辖区。
- 天启、绍宋的地方官多是「一职多员额」的无名席位（如知州·知军·知监 ×40），辖区要挂在每个在任者那一行上（`actualHolders[i].jurisdictionId`），任命时写入；无人的席位由分派按地块现算。
- 新字段要同步补进五处白名单，否则设衙、改制时会被丢掉：新职位工厂、章程职位表、章程校验、改制排队复制表、改制去重键。
- 通用任命现在不生成 `appointmentId`，而政绩账按任期记账，要补上。

### 4.2 分派规则

一件事生出来后：

1. **找候选**：职权覆盖本事类、辖区覆盖事发地点的所有职位。
2. **定主办**：候选里辖区最小的那个（最贴近地面的官先办）。
3. **定上呈链**：从主办沿 `reportsTo` 往上。链有多长，取决于主办选了什么处置：选「足额催征」，到府核转就结了；选「转详请蠲」，要一路上到元首。
4. **抄送监察**：有监察权、覆盖此地的职位收到知会。知会不占他们的亲办额度，但数对不上时会生出监察事（第六章）。
5. **出缺**：主办职位出缺时，依次找署理（`OfficeHolderState` 现有的署理与请假代理）、上官兼管；都没有，就由本衙门胥吏照惯例办，侵渔加重。
6. **无专司**：没有任何职位覆盖的事，送到最近的有总领之权的上级（省道主官，再上是元首），标「无专司」。无专司的事积压多了，就是该改制的信号。
7. **并管**：两个辖区同样大小的职位都覆盖同一件事（职权重叠），两边都收到。先动手的算主办（争办）；都不动手就是推诿，过期后自动生成一件「争办裁断」送到两者的共同上级。

### 4.3 名义分派与实际分派

- **名义分派**写在章程里，属宪法，由编辑器与改制定。
- **实际分派**由人的行动改变，属演绎：
  - 皇帝把某类题本的批红交给司礼监或内阁（委政，第十一章），这类事的「批准」一站就换了人。
  - 权臣截留奏疏（现有权臣机制已有雏形），就是在链上插了一站，可以压下、改写、放行。
  - 上官把下属的详文压下不报，事的状态变成 `buried`，过期照样算下属的账——除非有人揭出来。

实际分派只能由一次有记录的行动造成（委政诏令、截留阴谋、压下处置），不能由数值阈值自动出现。

### 4.4 改制就是改表

设衙、裁衙、移权、改统属，改的都是这张表。**已经在途的事按旧链走完，新生的事按新表分派**，保证确定性。改革自己会长出政治：

- **裁中间层**：下面的题本直达上面，上面的案头被压垮，逼出新的中间层。明初废中书省，六部直达御前，后来内阁票拟坐大，就是这个过程。
- **职权重叠**：新旧衙门都管同一类事，于是争办或推诿，一路闹到共同上级。东厂与锦衣卫、刑部，总督与巡抚，都是这类戏。
- **改制本身也是一件公事**：官员上疏请设某衙门，疏进元首案头或交廷议，准了才落成章程。现有设衙章程（`tm-office-charter`）已有品级、员额、职权、月俸，补上 4.1 节四项就是完整的分派定义。

### 4.5 文书流上的五种权

皇帝在顶端。从部院到元首之间的每一站，本质上都是在文书流上握着某一种权。本稿在现有九权之外，补五个**文书流权**（抽象键，名字归朝代包）：

| 抽象权 | 做什么 | 明 | 唐 | 宋 |
|---|---|---|---|---|
| `intake` 收呈 | 接收并转呈下面来的文书，可延搁 | 通政司 | 中书省受表 | 进奏院、通进银台司 |
| `drafting` 票拟（已有） | 替元首拟好处理意见 | 内阁 | 中书舍人 | 中书门下 |
| `assent` 批 | 最终定夺 | 皇帝；可委司礼监代批 | 皇帝 | 皇帝 |
| `veto` 封驳 | 把定夺退回重议 | 六科给事中 | 门下省 | 给事中 |
| `dispatch` 抄发 | 把定夺发下执行 | 六科 | 尚书省 | 中书门下 |

表中各朝的对应只是举例，以剧本配置为准。剧本里哪些职位握这几种权，由编辑器配；没配的朝代，链上就没有这一站（唐制可以没有「票拟」，蒙古汗廷可以只有议事会）。**同一套分派代码，适配不同朝代的中枢。**

数据底子是现成的：天启官制树里内阁（「票拟天下事」，首辅黄立极）、通政使司（「掌奏疏转达」，通政使杨所修，职掌里写着「阉党常扣压东林奏本于此」）、司礼监（掌印王体乾，秉笔魏忠贤，李永贞「代帝批红」）、六科（「封驳诏旨」）都在，只是职责写在描述文字里，职权字段一个也没配（三部剧本里「票拟」权出现 0 次）。晚唐有政事堂、门下给事中、中书舍人、枢密使，绍宋有门下给事中、中书舍人、谏院、通进银台司。给这些职位配上文书流五权，是交数据线的活。

九权现在在代码里抄了五份、编辑器只认其中六种（附录 A 节）。本稿要求收成一张词表作唯一真源，九权与文书流五权都从这里读。

### 4.6 文书在路上的时间

文书上呈下达要按路程花时间，远近有别。**路程由代码算，不交给 AI 判。**

- **算法**：用省道二期已有的 `TM.MapRouteDays`（`web/tm-map-route-days.js`）。取地块中心点换算成经纬度（晚唐、绍宋用地图自带的投影，天启用经纬参照点拟合），沿地块邻接走最短路，按大圆距离累加。
- **驿速**：常行每日 100 公里（模块现值）；灾伤、军情、限期将到的事走加急〔初值：每日 300 公里〕。模块现在只有常行一档，要加一个速度参数。
- **两站各在哪**：每个职位的驻地取其辖区的治所地块；省道主官驻首府；部院在京师。在京各衙门之间距离为零，当日可达。
- **走不通**：邻接断了（如被敌占隔断），按模块现有缺省估 10 日，标「估」。
- **一回合里怎么走**：回合结算时，文书在这一回合的天数里能走到哪站就走到哪站，沿途各站当场处置；走到玩家那一站就停下，等玩家下回合批。结算中途新到某站的文书，那一站的官员即使属于第一层，也按第二层规则办（来不及调 AI）。
- **算进限期**：路上耗掉的日子算进限期，所以偏远地方的事更容易逾期，这就是「鞭长莫及」。
- 举例：天启一回合 30 天，陕西一府的蠲免请求经省道、户部、通政、内阁，大约一回合内到御前；晚唐一回合 10 天，要走两三回合。

### 4.7 流程即权责，改制即重分权责

每一类事都有自己的**流程**：从哪一站起、经过哪几站、每一站要握什么权、做什么（主办、核转、批准、封驳、抄发、知会），以及办完之后考什么。流程写在朝代包的事类目录里，是宪法。

- **一站就是一份权责。** 某个职位握着某一类事流程上的某一站，就对这类事有这一站的权（能做哪些处置），也担这一站的责（考成记哪几项、出了事牵连到它）。
- **一个官的玩法，就是他握着的那些站。** 把一个职位在所有流程里占的站汇总起来，就是这个官的「权责表」：他会收到哪些事、能怎么办、被谁考、考什么。知府的玩法、巡抚的玩法、户部尚书的玩法、通政使的玩法，都从这张表里读出来，不用逐个官名去写。
- **改制的本质是把权责重新分给不同官职。** 所以「移权」是改制的核心动作：把某一类事流程上的某一站，从甲职移给乙职（例如把票拟之权给内阁、把钱粮核转从布政使移给巡抚）。增设、裁撤、合并都可以看成移权的组合——增设是把一些站移给新职位，裁撤是把它的站移回上级或移给别人，合并是把两份权责并到一处。现有改制管线只有增设、裁撤、合并、改名，没有移权，要补上，而且要作为主要的一种。
- **改制的阻力来自权责的得失。** 谁失去了哪几站、谁得到了哪几站，逐人算得清楚；失去的一方反对，得到的一方支持。现有改制抵抗分已经有「新衙门与在任官职权重叠就算夺权」的雏形，改为按流程站逐项计算。
- **流程表本身要能看。** 编辑器里按事类列出流程和各站由谁握着；游戏里每个职位能看到自己的权责表（这也是新手理解「这个官怎么玩」的入口）；改制诏令拟好后，先预览权责怎样重分、谁得谁失。

第十四章 14.4 节把钱粮八类事的流程逐站列了出来，是第一份流程表。

## 五、办：处置即行动

### 5.1 处置的输入是意向声明

处置不是选择题。玩家对一件事写**批语**（自由文字），AI 把批语归到合法的处置类型上，代码按权限和账本校验后执行——和现在诏书的做法一样。案头同时列出这类事常用的几种处置，点一下就等于写了对应的批语。

NPC 这边，AI 或性情规则直接产出有类型的处置加一句理由，同样过校验。

### 5.2 一个处置由什么构成

```js
{
  verb: 'collection.strict',          // 处置类型（事类目录里定义）
  params: { share: 1.0 },             // 参数，如催征成数、截留数额
  authority: 'county',                // 需要的权限额度；不够就只能「上呈请示」
  effects: [...],                     // 宪法：对哪些账本、在什么上下限内起作用
  risks: [...],                       // 可能的反噬及其条件（看世界状况，不看能力）
  energy: 10,                         // 亲办耗的精力（按事的大小 5～15，见 5.3 节）
  gate: { ability: 'administration', min: 60 }   // 招式门槛（可无）
}
```

每种处置对账本的作用都写在事类目录里，是宪法；AI 只负责「选哪种、为什么、说了什么」。

### 5.3 能力放在哪

能力照样重要，但只在四个地方起作用：

| 能力管什么 | 规则〔初值〕 |
|---|---|
| **亲办额度**：每回合能亲手办几件 | 玩家用**精力**付：亲办一件事按大小耗 5～15 精力，和常朝、廷议、问对共用一个池子，要不要亲办、办几件由玩家自己权衡。NPC 按件数：元首 5、堂官与督抚 4、府州县 3、不当官的人 3（家事与乡事）；另按相关能力 ±1（≥75 加一，<35 减一）；病、老、心力交瘁再减。每位幕宾在其专长上替主人多办 1～2 件，不耗主人精力 |
| **看清度**：看得清几分实情 | `0.25 + 0.5×相关能力/100 + 0.15×属吏熟练 − 0.2×胥吏蒙蔽`，夹在 0.1～0.95。你看到的数 = 呈报数 + 看清度 ×（实数 − 呈报数）。看清度 ≥0.6 且差额超过一成时，案头标「此数可疑」 |
| **招式门槛**：有哪些招可用 | 例如「清查诡寄」要相关能力 ≥60，或有一位能力 ≥60 的钱谷幕宾 |
| **风险**：冒险的招出事的可能 | 主要看世界状况（例如严催时本地民心 <40，才有激变之虞，概率随民心下降而升）；能力只把反噬概率压低至多两成 |

结果的方向由选择决定：同一个能臣，严催和宽限的结果截然相反；同一件事，庸官照惯例办和能臣照惯例办，结果几乎一样——差别在能臣看得出窟窿、有更多招可用。

### 5.4 依例与胥吏

没被亲办的事，由主办衙门的胥吏按**成例**去办。明清的日常政务本来就是这样跑的——顾炎武说「今夺百官之权，而一切归之吏胥」。

每个衙门带一份胥吏风气（剧本可配，缺省按朝代包与年代）：

```js
clerks: {
  graft: 0.15,       // 侵渔：经手银粮漏进私囊的比例（明末缺省偏高）
  cover: 0.30,       // 蒙蔽：往上报时把欠报成完的比例
  skill: 0.50        // 熟练：影响看清度与依例办的稳定性
}
```

- 依例办 = 成例处置 + 侵渔 + 蒙蔽。省心，但钱在漏、数在假。
- 胥吏风气能被行动改变：「整饬胥吏」「裁汰冗吏」本身是可以写进批语的处置，要花精力、会得罪人（胥吏也有靠山）。
- 主官长期不闻不问，风气会自己往坏处走〔初值：每年侵渔 +0.01〕。

### 5.5 幕宾

幕宾是真实人物，多是生员、举人、落第士人，由官员私人延聘，束脩从官员私产里出。

- 幕宾按专长（钱谷、刑名、书启……）替主人办一部分待办的事，用的是**幕宾自己的能力**，遵的是主人定的方针（宽、严、清、稳）。
- 幕宾比胥吏办得好，但他有自己的心思：可能收礼、可能泄密。他知道主人的底细，一旦反目就是现成的把柄。
- 对不当官的玩家，**入幕本身是一条出路**（第十章）。

### 5.6 NPC 怎么办事：三层

几百个官员不可能都调 AI。

| 层 | 谁 | 怎么决断 |
|---|---|---|
| 一 | 与玩家有关的人（上官、下属、同僚、门生、姻亲、对头）、身居要职者、本回合显著度最高的若干人 | AI 批量决断：每次一批数人，给人物卡、浮上来的事、合法处置、各方压力，产出有类型的处置加批语，过校验 |
| 二 | 其余具名官员 | 性情规则：按 8D 性格（贪念是其中一维）、五常、野心、忠诚与利害压力给各处置打分，取最高分（带种子的轻微随机） |
| 三 | 无具名在任者的职位（大量州县）、低显著度的事 | 整批照惯例办，汇总结算 |

第一层在玩家思考期间成批调用 AI，结果暂存，到回合结算开头和其他处置一起定稿（14.7 节）；预算与现有每回合调用上限共用，不另开口子。第二层的打分：

```
分(处置) = 本分(处置)
         + Σ 性情系数 × 性情值            // 刚严者偏严催，仁厚者偏宽限，贪者偏包揽侵渔，圆滑者偏推诿依例
         + 压力(处置)                      // 上官交办、座主来信、考成期限将到
         + 私利(处置) × 贪念
         − 风险(处置) × (1 − 胆量)
```

### 5.7 履职度的去留

现有履职度（`tm-office-dutystate.js`：向「域才 × 0.6 + 五常 × 0.4」漂移，高低两档作用于实征率与腐败）在新范式下**退出驱动**：

- 某个领域被公事接管后，该领域的履职度档位效果停用，改由处置结果起作用。钱粮先接管，所以征税权那一档先停。
- 履职度本身保留为**只读的派生读数**：由政绩账滚动算出，供界面和 AI 提示用，不再反过来改世界。
- 按叙事关键词加减分的 `tm-office-action-evidence.js`，在已接管的领域同样停用——政绩账里有真实处置记录，不必再猜。

## 六、责：记账、考核、连坐

### 6.1 政绩账

每一站处置都记进经手人**这一任**（按任职的 appointmentId）的政绩账：

```js
{ matterId, domain, kind, role, disposition, turn,
  outcome: { due, collected, remitted, deadlineMet },     // 有类型的结果
  gap: { reported, actual },                              // 呈报与实情之差（被揭出来之前只有系统知道）
  stakeholdersServed: [...], stakeholdersHurt: [...] }
```

政绩账是考核、弹劾、交代的唯一依据。

### 6.2 考成指标

由职权推出，名字归朝代包：

| 职权 | 考什么 |
|---|---|
| 征税 | 限内完欠率、起解是否及时、有无亏空、奏销是否属实（被揭出后） |
| 刑狱 | 积案、翻案、冤案（后续领域） |
| 监察 | 纠劾是否属实、有无失察 |
| 其余 | 随领域接管逐步补 |

### 6.3 考核者也在办事

考核不是一个定时公式，而是考核者案头的公事，考核者照样有交情、有私心：

- **考满**：任满时，考功一类的职位案头出现「考某人」一事。处置是称职、平常、不称职，写考语；座主、同年的来信会压在这件事上。
- **京察、大计**：周期性地成批出现在吏部与都察院案头。现有 `_tickJingcha` 改为读政绩账、由考核者处置，不再直接按分数黜陟。
- **科道风闻**：政绩账里数对不上、被清查过的士绅来告、幕宾胥吏泄出的底细，都会在科道官案头生出「风闻」事。处置是纠劾（写成弹章上呈）、按下不发，或者拿来当把柄。
- **巡按巡视**：巡视一地，就是在当地的事上把看清度拉满——这是「揭真」的正路，接奏报失真层现成的揭真许可。
- **交代**：新官接任，案头第一件事是交代。前任留下的亏空，是揭报（结仇）、分赔，还是替他瞒下（背上干系），是很典型的一出戏。

张居正的考成法正是这个结构：部院立限，六科稽核部院，内阁总查六科——考核本身就是一条公事链。

### 6.4 连坐

- **举主连坐**：被荐举的人考劣或获罪，举主的政绩账记一笔「所举非人」。
- **上官失察**：属官的贪墨被揭出，负有监察之责的上官记一笔「失察」。
- 连坐只记账、给考核者看，罚不罚、罚多重，仍是考核者和元首的处置。

### 6.5 后果全是人的决定

升、降、调、罢、革职留任、下狱、抄家——每一项都必须是某个人的处置，经现有写口落地（任免、功名升降、下狱、抄家）。弹章是元首案头的一件事：玩家是皇帝就由玩家批；不是，就由扮演皇帝的 NPC 批。

## 七、人：关系、人情、把柄

### 7.1 制度造出来的关系

| 关系 | 怎么来 | 有什么后果 |
|---|---|---|
| 座主—门生 | 科举：考官与所取之士 | 门生在会推、弹劾时被期待站在座主一边；座主有庇护之责 |
| 同年 | 同一榜 | 互通消息、说情的现成门路；现有同年集会 |
| 举主—被举 | 荐举 | 连坐（6.4）；知遇之恩 |
| 上官—属官 | 任命 | 上官写考语、摊任务、担失察之责；属官要看上官脸色 |
| 同僚 | 同一衙门 | 会办、争办、推诿 |
| 幕主—幕宾 | 延聘 | 幕宾替主人办事，也知道主人底细 |
| 师生 | 讲学、书院 | 学脉；门生传衣钵的根（第八章） |
| 同乡 | 籍贯 | 说情门路；会馆 |
| 姻亲 | 婚姻 | 两家结盟；抄家时牵连 |
| 同党 | 党派（现有） | 议程、弹劾中的站队 |

这些关系在它们的来源事件发生时自动建立（放榜、荐举、任命、延聘、成婚），不靠 AI 自由生成。

**先并账。** 现在光是师承、座主门生就有七套存储互不相通（科举的座主图、剧本的门生网、荐辟的荐主、廷议的门生表、关系标签等，附录 F 节），上官属官只是一段自由文字，同乡、同年的规范标签没有任何写入路径。所以要立一本**制度关系账**作为唯一真源：

```js
GM.ties = {
  byId: { 'tie-…': { kind: 'examiner' | 'cohort' | 'recommender' | 'superior' | 'colleague' | 'patron' | 'teacher' | 'native' | 'kin' | 'party',
                     from, to, since, strength, origin: { kind, ref } } },
  byChar: { [charId]: [tieId, ...] }
}
```

- 上官属官、同僚、同乡、同党是**派生的**：由官制树的统属（4.1 节）、籍贯、党派现算，查询时给出同样形状的记录，但不落进账里、不存副本。
- 座主门生、同年、举主、幕主幕宾、师生、姻亲是**事件生成的**：由放榜、荐举、延聘、讲学、成婚写入。
- 旧的七套存储改为从这本账读出的视图，逐步退役。

### 7.2 四种筹码

| 筹码 | 怎么来 | 怎么用 |
|---|---|---|
| **人情** | 你照顾了别人的请托、荐举了他、在危难时帮了他 | 请他照顾你的事、在会推时投你一票、保举你的子弟 |
| **把柄** | 别人知道你某次处置的实情（呈报与实情不符、收了礼、枉了法） | 要挟你，或者揭发你（生成监察事） |
| **名望** | 政绩账与公议：清名、能名、贪名、酷名 | 影响会推、荐举、元首观感、乡里声望 |
| **圣眷** | 元首对你的观感 | 特简、危难时的庇护 |

- 圣眷在玩家是皇帝时，由你的所作所为算出来：准驳过他几次折子、嘉奖斥责、召对多少、升降调转。NPC 据此揣摩上意，不另设一个玩家看不见的「好感」。
- 人情是一本账：谁欠谁、因哪件事、多重、何时欠下。现有关系里的 `owesFavor` 只增不减、没有任何「讨还」的用处，并入这本账后才有消费方。
- 把柄是**信息**：谁知道了什么。它随私书传播，也会因知情人死亡、被收买而消失。现有 `holdsSecret` 字段全库没有写入点，由这本账取代；现有「揭人隐私」交互改为消费这本账。
- **关系要在「交付」那一步落账。** #89 之后，担保、举荐、联姻、师徒、托孤、密信这些交互在正式运行时都改走「请求—答复—交付」的信件计划，交互表里规定的亲疏、人情、标签加减实际不落地（附录 F 节，已核代码路径）。新设计里，这些效果挂在计划的交付回执上：信送到、对方应了、事办成了，人情和关系才记账。

### 7.3 私书

私书走现有的鸿雁（有路程、会延误、可能被截）。鸿雁现在按「同省 200 里、默认 1000 里」粗估路程，改用 4.6 节同一套经纬度路程。四种用途：

- **请托**：为某件事说情。它会作为「压力」挂到对方案头那件事上。
- **结纳**：通好、送礼，增进关系。
- **通消息**：把你知道的事告诉对方——包括别人的把柄。
- **投书**：求入幕、求荐举、求拜门下。

### 7.4 关系怎么压在事上

对一件事的持有人，每位利害人按「与持有人的关系强度 × 此人分量」形成一股压力，方向是他希望的处置：

- **玩家**：案头这件事旁边列出「谁为此事来信、谁在盯着」，你看得见压力，自己决定照不照顾。
- **NPC**：压力进 5.6 节打分式的「压力」项。
- **照顾了**：欠你的人情增加；如果处置不正当，知情人手里多一份把柄；政绩账上可能留下偏差。
- **不照顾**：关系受损，可能结怨。

这样，关系不是另起的小游戏，而是嵌在办事里。

## 八、家与门生：扮演单位与传承

### 8.1 家

「家」不另起炉灶，**在现有 `GM.families` 上升格**。现状（附录 F 节）：剧本 `families[]` 开局载入 `GM.families`（天启 37 族，已有门第等级、声望、祖籍、当家人、继承人、成员等文字字段），每月按在任族人结算家族声望；但人物的 `family` 字段有字符串、`{clanId, role}`、`{name, core, extended}` 三种形态并存，经济引擎的 `GM.clans` 从来没有写入点，晚唐的人物经济账又另记 `household:<id>`。三处要合成一个实体：

```js
GM.families = {
  'family-gaoyang-sun': {
    id, name: '高阳孙氏',           // 郡望或堂号；旧键（族名）保留为别名
    seatRegionId,                   // 籍贯（祖籍地块）
    headId,                         // 当家人（人物 id，不再是文字）
    memberIds: [...],               // 入册族人
    standing: { tier, score },      // 门第：沿用现有等级表与声望
    estate: { land, houses, silver, businesses },   // 公中家产（与人物私产的分界见附录）
    lineageTrust: { land, silver }, // 族田、义庄：不随分家拆散
    shadowRights: [...],            // 荫：谁因谁的品级获得荫补资格、是否已用
    marriageTies: [familyId, ...],  // 姻亲
    reputation: {...},              // 家声：清誉、恶名（如名列逆案）
    feuds: [...]                    // 世仇
  }
};
```

- 人物的 `family` 统一成一个家 id；经济引擎的族产、株连、抄没改读这个实体（`GM.clans` 退役）；晚唐的 `household:<id>` 对到家 id。
- **入册**：现在剧本里「有在册子女的活人」极少（天启 216 人中只有 9 人），子女大多只是 `familyMembers` 里的文字。玩家的家、以及第一层 AI 关注的家，开局时把文字里的直系亲属确定性地建成人物（沿用现有 AI 家事补录的写法），否则谈不上传承。
- 玩家控制一个家，通过它的**当家人**——也就是视角人物（第九章）。
- 当家人可以对家人下**家令**：让儿子进京应试、给女儿议亲、派侄子去经营产业。家人大体听从，但他们是有自己心思的 NPC，可能阳奉阴违。
- 家人的公事不归玩家办：儿子做了知县，他的案头由他自己办；你能做的是写家书、托人情。

### 8.2 传承顺序

当家人死亡时，按家法（8.4 节）找继任者：

1. **子孙**：家法定默认人选（明制缺省是嫡长）。玩家可以在家法允许的人里改选，改选非默认人选会伤家族和气。
   - **可以直接扮幼主。** 继任者未成年时，玩家照样扮他；家政由摄家政者代管（按家法，可能是主母，也可能是族中长辈）。摄家政者是 NPC，替幼主下家令、管家产，可能尽心，也可能侵吞。幼主自己能做的有限（读书、拜师、结交同窗、写信），到了成年（朝代包定，如十六岁）才亲掌家政。
2. **立嗣**：没有儿子时，从同宗过继一人——这是历史上最主要的续嗣办法。
3. **门生传衣钵**：同宗也无人可立，可以把衣钵传给一位门生。门生成为新的视角人物，**玩家改扮门生所在的家**；原来的家留在世界里，由 AI 接管，两家之间留有师恩与世交。衣钵传的是**学脉与人脉**（文名、师门声望，先师的门生故吏认他），**不是家产**，家产归原来的家。
4. **终局**：以上都没有，游戏结束。

这与现有「终局等于玩家角色被杀」的范式一致，只是扩成「玩家所扮之人死亡且无人可承」。

现成件与要改的地方：

- 现有 `resolveHeir` 已支持指定继承人、子嗣、长幼、推举几种法，第 1、2 步直接用它，只是把「家」作为范围。
- 现有 `transferPlayerControl` 把继承人**写死设为「皇帝」**并改势力首领（附录 E、F 节）。要拆成两件事：换视角人物（任何家都要）和继承皇位（只有皇室、且按现有继统与合法性门）。
- 门生传衣钵是新动作；师承关系要先并成一本账（7.1 节），才知道谁是门生。

### 8.3 带到下一代的东西

| 传什么 | 怎么传 |
|---|---|
| 门第 | 整家继承；影响婚姻、荐举、士林观感 |
| 荫 | 高品级先人留下的荫补资格（现有门荫：三品以上可荫一子） |
| 家产 | **诸子均分**：当家人死后，家产在诸子间分开，当家人只拿自己那一份。这是和 CK3 长子继承最大的不同——家业会一代代被分薄。族田、义庄不分，是保住家业的办法 |
| 世交 | 先人的门生故吏、同年，对继任者降一档仍认这份交情 |
| 家声与世仇 | 整家继承（阉党之名会跟着走） |

官职不传。继任者要自己去考、去捐、去求荐，从头爬。

现状里遗产只在经济引擎判定「老死」时才分，AI 叙事写死的人不分；旧路径要求 `family.children`，而 `family` 多是字符串，实际上永远不触发；分家只作用于从不写入的 `GM.clans`。所以要立**一条死亡—继承—分家的单一管线**：任何死法都经现有的死亡裁决口，再按家法分产、定当家人、转荫与世交。现有门荫是「新造一个荫生」，改为优先荫在册的子弟，没有在册子弟时才新造。

### 8.4 家法与风俗

谁能承家、几岁成年、未成年时谁摄家政、女子能否承家、家产是否诸子均分、能否立嗣——这些都不写死，由**家法**定。家法从三层来，后一层盖前一层：

1. **朝代包缺省**：按史实给（明制：嫡长承家、诸子均分、寡母可抚孤摄家政、女子不承家、同宗可立嗣）。
2. **开局风俗设定**：开局时玩家自己选这一局的社会风俗，至少三档——史实、宽松（如许女子承家但男丁优先）、不限（男女同列）。
3. **本家家法**：每个家可以有自己的家法（剧本可配），游戏里也能改。

家法与风俗**在游戏里可以被推演改变**，像 CK3 改继承法那样要条件、要时间、有阻力：

- **改本家家法**：当家人下家令即可发起；族中长辈、有利害的子弟会有异议，关系受损，甚至闹到分家或族讼。
- **改社会风俗**：一家改不了天下。要么朝廷改律（皇帝下诏，交礼部一类衙门办，是一件公事，按改制那样有阻力），要么士林风气慢慢转（书院讲学、清议推动）。AI 推演接受程度与反弹，代码只管「风俗改了之后家法怎么判」。

数据上，风俗挂在社会一层（`GM.customs`：女子承家、诸子均分、立嗣、成年年龄、摄家政人选），家法挂在家上（`families[].houseLaw`，没写就用风俗）。

### 8.5 皇室也是一个家

皇帝的家就是皇室。现有储君继统（`resolveHeir` 与合法性门）不变；变的是**失去皇位不等于游戏结束**：被废、被俘、国破之后，只要皇室还有人，玩家可以接着扮演宗室成员——这就是不当官的玩法（第十章）。现有的废帝、傀儡、北狩可玩态正好是这条路的起点，但它们现在只是写了标记、没人读（第九章「渠道可用矩阵」）。

另有一个现成的坑要一起填：继位时 `transferPlayerControl` 只更新 `GM.playerInfo`，不更新 `P.playerInfo`，而回合推演找主角读的是后者，继位后 AI 很可能还把先帝当主角（附录 E 节，读码所得，待实测）。

## 九、身份与五渠道

### 9.1 身份

每个人物的身份由几层叠成：

| 层 | 取值举例 | 给了什么 |
|---|---|---|
| 官职 | 在任、署理、候补、革职留任、无 | 公事案头与职权 |
| 出身 | 进士、举人、监生、生员、荫生、吏员、武举、军功、无 | 入仕资格；士林地位 |
| 绅衿 | 在籍官员（致仕、丁忧、告假、罢官闲住）、举贡生监 | 优免、见官不跪、可谒见地方官、可联名；乡事案头 |
| 家中地位 | 当家人、子弟 | 家令 |
| 其他 | 宗室、外戚、宦官、商、军户、僧道 | 各有专门的门路与禁忌（如宗室不得出仕） |

身份决定四件事：**案头有什么事、能用哪些手段、看得见什么、谁能拿你怎么样**（官员受考核弹劾，绅衿可被褫革功名，百姓受刑责）。

**有没有官，以官制树上的实际任职为准，不看头衔文字。** 现在人物的 `officialTitle` 被当成万能字段，装着皇后、「已罢」、首领、海商、举人这类非官身份；而功名推定、NPC 行为候选、科举排除考生、铨选判断都把「头衔非空」当成「有官」（附录 F 节：张溥是举人、顾炎武是少年，都被推成「生员」）。身份要改成由三处现算：官职取 `OfficeHolderState` 的在任记录，出身取功名 `TMGongming`，绅衿与家中地位取新的身份字段；头衔只作显示。这是不当官玩法的前提。

### 9.2 五渠道按身份配置

五渠道不推翻。本稿把它们抽象成**令、批、书、见、行**五种动作，皇帝只是其中最上面的一种配置：

| 渠道 | 皇帝 | 京官、地方官 | 在籍乡绅、生员、族长 | 商人、布衣 |
|---|---|---|---|---|
| 令（诏令） | 下诏、敕 | 发公文：对下札付、牌票，对民告示，对上题奏、详文 | 家令；族规、乡约；联名公呈 | 家令；递呈（只能递状，不能直接行文） |
| 批（奏疏批复） | 批红 | 批详、堂判：处置案头公事 | 处置乡事、家事；调处纠纷 | 处置家事、生意 |
| 书（鸿雁传书） | 手札、密谕 | 私书：请托、结纳、通消息 | 同左；投书求荐 | 同左；多靠中人引介 |
| 见（问对朝议） | 召对、廷议 | 谒见上官；接见下属与士绅；按品级参与会推、堂议 | 谒见地方官；文会、诗社、讲学 | 拜谒须有门路或出钱 |
| 行（主角行止） | 巡幸、亲征 | 赴任、巡视、告假、丁忧、致仕 | 进京应试、游学、回籍、团练 | 经商、迁居 |

每个渠道里能用的动作，由身份和职权筛出来；处置的输入一律是意向声明（5.1 节）。

**渠道可用矩阵。** 每种身份（含失位状态）对应一张「哪些渠道开、开到什么程度」的表，由视角人物的身份现算。现状是：废帝、傀儡、被俘这几个标记写了却没有任何地方读，失位以后五个渠道照样全开（附录 E 节）。矩阵立起来之后，失位才真正改变你能做什么——被俘的皇帝只剩书信与行止，被废的皇帝落到宗室那一档。

**精力按人物。** 现在精力是全局一个值（上限 100、每回合回满，只有朝议、问对扣），改为挂在视角人物身上，上限随年老病弱下调；亲办公事也从这里扣（5.3 节）。

**行止要有结构。** 现在「主角行止」是诏令面板里的一栏自由文字，出巡、移驾没有结构化入口，玩家本人要移动只能写进诏令让抽取器去认。新设计里，行的常用动作（赴任、巡视、进京、回籍、告假、丁忧、致仕、游学、经商）是有类型的，自由文字照样可写。

### 9.3 视野

你看得见什么，也由身份决定：

- **元首**：层层呈上来的题本（数是呈报数），以及厂卫、密折这类揭真门路。
- **官员**：辖区的册籍（下属呈报的数，可能是假的）、邸报（朝廷公开消息）、私书。
- **不当官的人**：本地亲见之事、邸报（绅衿能看到）、私书、传闻。

实现上沿用两套现成件：奏报失真层（呈报数与实数）和 #90 的人物限知（谁知道什么）。第一刀只把「案头上每件事的事实」按看清度过滤；整个界面按视角人物过滤放到后面的阶段。

### 9.4 对前端重做的约束：案头即身份

前端重做正在打地基，这一条要现在就定：

- **身份是界面的一等参数。** 新前端的信息结构不能把「皇帝」写死：顶栏读数、案头内容、五渠道入口、地图的可见范围，都要从视角人物的身份取。
- **书案外壳按身份换陈设**：皇帝案上是玉玺、朱笔、题本；部堂是大印、签押房、咨文；知县是县印、朱签、状纸；不当官的人是书斋、家书、账簿。甲方向的「器物即功能」正好推广成「看书案就知道你是谁」。
- **案头是主界面**：每回合浮上来的几件事、来信、来谒，是玩家打开游戏第一眼看到的东西。

美术与界面的具体做法归前端重做那条线，这里只定信息结构上的约束。

## 十、不当官的玩家

### 10.1 可以是谁

| 身份 | 立身之本 | 典型处境 |
|---|---|---|
| 在籍乡绅（致仕、丁忧、罢官闲住） | 旧日官声、门生故吏、家产 | 在乡里说得上话，随时可能起复 |
| 举人、贡生、监生、生员 | 功名、文名、同年同学 | 一边应试，一边入幕、讲学、结社 |
| 布衣士人 | 学问、文名 | 读书应试是正途 |
| 商人 | 财力 | 与官府打交道（盐引、关税、捐输），捐纳入仕 |
| 族长、豪强 | 族人、族田、乡里势力 | 乡里的实际主事者 |
| 幕宾 | 主人的信任、专长 | 不在官籍，却在衙门里办事 |
| 宗室 | 宗禄、皇族身份 | 不得出仕；宗禄常年欠发 |

普通农夫工匠能动用的手段太少，第一阶段不作为可选开局；将来走民变起事那条线（现有民变实体化）。

现成的人：天启剧本本朝在世的 99 人里，约 19 人没有实职或已离职（罢、告归、丁忧、致仕、在学），例如剧本身份为「太仓举人」的张溥、「昆山少年」顾炎武。现成的场子：书院与结社已有实体（东林、首善、关中书院与复社，有真实的山长人物、生命周期，能衍生党派），正好是清议这条路的底子。缺的：宗族、乡约、义仓、团练没有任何实体；生员、举人在科举里只是统计数，不会成为人物，在册人物也不能应考（附录 F 节）。

### 10.2 三张案头

1. **家事**（人人都有）：婚嫁、子弟教养与应试、置产分家、丧葬、人情往来、家讼。
2. **乡事**（有身份者）：饥荒时开不开义仓、修不修桥、办不办团练、宗族纠纷怎么调处、要不要联名呈请县官蠲缓。乡事的「分派」不按官职，而按乡里声望：功名越高、门第越重、出钱越多，乡事越落到你头上。
3. **案外**：官员案头的事，你是利害人。你的田在清丈之列、你的族人牵进命案、县官要摊派捐输——你能做的，是托人情、递状子、捐输换人情、联名施压、在清议里造声势，或者揭发他。

### 10.3 手段

| 手段 | 做什么 | 走哪条渠道 |
|---|---|---|
| 请托 | 为某件事给经手官员施压 | 书、见 |
| 递呈、告状 | 把一件事送进官员案头（生成公事） | 令 |
| 捐输 | 出钱出粮给官府的事（赈济、修城、军饷），换名望与人情，有时换虚衔 | 令、见 |
| 联名公呈 | 士绅联合施压（生成一件分量加重的公事） | 令 |
| 揭发 | 把某官的把柄送到科道或上官手里（生成监察事） | 书 |
| 清议 | 结社、讲学、诗文唱和，影响官员的名望与科道的风闻 | 见、书 |
| 包揽、诡寄 | 替别人代纳钱粮抽成，或把别人的田挂在自己名下避役 | 批（家事与乡事） |
| 经营 | 置田、放贷、开店、领盐引 | 批、行 |

包揽、诡寄是钱粮竖切里官员那一侧「清查诡寄」的对面——同一件事，官员与士绅各坐一边。

### 10.4 出入仕途

不当官不是一种单独的模式，而是同一个人会经过的状态：

- **进**：应试（现有科举）、捐纳（现有捐纳）、荐辟（现有荐贤）、门荫（现有荫子）、入幕后被主人保举、办团练立军功。
  - 应试这条路依赖科举那条线：要让在册人物（包括玩家）能报考，生员、举人要能成为人物。科举大改完工前禁发版，所以这部分要与科举线协同排期。
- **出**：丁忧（二十七个月，夺情须元首特旨）、告病、罢官、致仕、被褫革功名。
- **回**：丁忧期满、起复、平反。

状态变了，案头跟着换：丁忧回籍的第二天，你的案头就从公事变成了家事和乡事。

### 10.5 两个例子

**一个致仕侍郎的一年。** 他回到老家，案头是乡事与家事。春荒，县里请他出面劝富户平粜，他开了自家义仓，乡里称颂，县官欠他一份人情。夏天，新任知县要清丈，他家挂着几十户诡寄的田。他写信给在户部当郎中的门生，门生回信说新知县是首辅的人，劝他别硬顶。他选择主动报出一半，把另一半留着——知县得了政绩，他保住了颜面和大半田租，却也让知县手里握了一份把柄。秋天，朝中起复的风声传来……

**一个生员的一年。** 他是寒门，没钱，文章好。春天投书入了知府幕中做钱谷幕宾，替知府处置了几件催科的事，眼看知府奏销要粉饰，他知道了实情。秋闱中举，座主是一位东林名宿，同年里有几个是阉党子弟。知府请他留幕，许诺保举；座主来信要他进京会试……他知道的那个实情，是他手里第一份把柄，也是他的第一份危险。

这两段里，每一个转折都是一次行动，没有一处是按能力自动结算的。

### 10.6 什么算输

家道中落、被褫革功名、下狱流放，都不算输，家还在就接着玩。只有第八章的「无人可承」才是终局。

## 十一、皇帝

### 11.1 皇帝的案头

皇帝的案头就是分派的最顶端：

- 各部院经收呈、票拟一路上来的题本（数是呈报数，附票拟意见）；
- 弹章、会推结果（待点用）、蠲免请求、奏销总册；
- 厂卫、密折（揭真门路）。

现有奏疏界面变成「御前题本」这一站的视图；现有 AI 生成奏疏继续作为显著公事的文字演绎来源。

### 11.2 诏令变成公事

这是皇帝玩法最大的变化。现在不少诏令被解析后直接落效（例如加派、开仓、借贷由 `extractEdictFiscalActions` 即时执行）。在已接管的领域里改为：

- 诏令下达后，生成对口衙门案头的公事，带期限，要复命（现有 `ImperialOrders` 的限期复命账就是考成法的雏形，直接用）。
- 实际执行取决于链上每一站的处置：同一道加派令，有的知县摊在大户身上，有的摊在小民头上，有的拖着不办，有的办了却报多了。
- 复命的数可能是粉饰过的。你想知道实情，就派人去查。

诏令效力（常制、有期、一次性）照旧；变的是「谁、怎么去执行」。

### 11.3 委政

元首的亲办额度也有限。题本太多，就得委政：把某一类事的批交给内阁、司礼监或某位重臣。

- 委出去，案头轻了，但那一站的实际分派就换了人，他们会按自己的心思批。
- 不委，留中的事越积越多，过期的事照样出后果。

万历怠政、天启时魏忠贤专权，都是这一条的历史原型。委政只能由诏令明确做出，可以随时收回。

### 11.4 钦差就是临时改制

派钦差（巡按、督师、钦差大臣）就是临时设一个职位，给它辖区和职权，事毕撤销。它走的是和设衙同一套分派，只是带到期时间。

### 11.5 与现有皇帝玩法的衔接

皇帝玩法不推倒重来。领域一个一个接管，没接管的领域照旧；每接管一个领域，那一类诏令改成生公事，那一类奏疏改由分派上呈。

### 11.6 皇帝是 NPC 时

玩家不是皇帝时，皇帝的案头照样有题本、弹章、会推要批，得有人替他批：

- **例行的照票拟批。** 这本来就是明代常态：内阁拟好，皇帝照批。
- **要紧的由 AI 决断**（第一层）：弹章、会推点用、大额蠲免、兵事，按皇帝这个人的性情、信谁、近来心绪来批。
- **皇帝的性情决定手感**：勤政的常改票拟、常召对；怠政的留中成堆，给权臣、宦官截留和代批留出空子——这正是 4.3 节说的「实际分派由人的行动改变」。
- 皇帝 NPC 的诏令同样落成公事往下走，玩家若在链上，就会在案头收到。

## 十二、时间与推演结算

> 同志 09-30 提：改回合制为「即时＋结算」。时间像 CK3 那样连续流逝，可以暂停，可以调一、二、三速；大推演由玩家在任意时刻按「推演结算」触发，覆盖自上次推演以来的不定长时段。一「回合」多长，由玩家自己定。
>
> 本章的现状依据见附录二 [survey-turn.md](survey-turn.md)（一回合的 AI 调用与确定性系统全表）。

### 12.1 现在的一回合是什么样

- 过回合一条管线：准备（prep）→ 预取 → AI（先征收、固定支出，再主推演 sc1 与写回）→ 诏令补录 → 系统步 → 渲染与收尾（奏疏生成、史记等）。**AI 写回在系统步之前**，系统步读的是本回合 AI 刚写回的世界。
- 系统步（`_endTurn_updateSystems`）：战斗裁决 → 子回合调度器（日、月、回合三档，七十多个登记项）→ 编年 → **全库唯一的 `GM.turn++`** → 五十多个引擎按「每回合天数 ÷ 30」缩放各跑一次。
- AI 调用：标准深度稳定 14 次，完整深度 17～18 次；另有预取、sc1 补救、势力调度、NPC 自主、回合后记忆任务等，整段生命周期没有固定上限。
- 三部剧本每回合天数：天启 30 日，绍宋 30 日，晚唐 10 日。
- **没有「只跑确定性、不调 AI」的现成路径**：没配密钥时，过回合的入口直接返回，系统步也不跑。
- `GM.turn` 在网页代码里约 2300 处，同时当日期、冷却、期限、周期触发、幂等戳和存档租约用。

### 12.2 三种时间

| | 是什么 | 谁推动 | 多久一次 |
|---|---|---|---|
| 日 | 游戏里的日历，最小单位一天 | 时钟；玩家暂停、调速 | 连续 |
| 节 | 确定性结算的步长，等于剧本的每回合天数 | 日历每走满一节，自动跑一次 | 固定 |
| 推演 | 大规模 AI 推演，覆盖自上次推演以来的全部日子 | 玩家按「推演结算」 | 玩家定 |

**节就是现在的回合拿掉 AI 之后剩下的部分**，分两截：

- **节首**：批复落地、诏令登记、定稿处置（第五章）、征收、固定支出，也就是现在准备步和 AI 步开头那几项；
- **节尾**：现有系统步原样跑，`GM.turn` 仍在这里加一。

节首里的批复落地、诏令登记，到时2 改成玩家下手时当场落；节首只留依赖节界的部分：诏令期限与驿递的起算、跨渠道去重、变量基线、事务快照（附录二第五节）。

所以全库确定性系统里按回合算的冷却、期限、周期触发、幂等戳，语义一处都不用改：一回合就是一节。AI 推演从回合里拆出来，另起推演序号；AI 各步自己的防重复标记改按推演序号记（12.5 节）。

没有现成的「只跑确定性」路径，节律执行器要新写；但它复用系统步，不另起炉灶，并自带快照：跑坏了就回滚到节前、停钟、报错。

### 12.3 两次推演之间发生什么

**每日**（确定性，不调 AI）：
- 日历推进；
- 人与文书在路上走（4.6 节的路程），到站就交给这一站处置；
- 事的期限、征期到点；
- #91 的日常往来（它已经按日推进：每日开几件、每日走几步、七日联络冷却、三十日超时）。

**每节**：节首、节尾依次跑完。节尾耗时可观（系统步里单个阶段超过 1.5 秒就会记慢），跑的时候时钟停一下，界面显示「月结」之类的字样。

**实时后台 AI**（小调用，不卡时钟）：
- 问对、常朝、朝议：进行时时钟自动暂停，结束后按所费时辰走表；
- 私书：寄出时就在后台生成对方的回信，路上的日子正好盖住模型的延迟；
- 票拟：题本走到御前一站时生成辅臣拟议；
- 来文正文：奏疏、申文到达前在后台写好；
- 第一层公事批：按到期先后成批跑；
- 势力调度、NPC 自主决断：沿用现在回合内调度的做法。

后台结果按**它所依据的对象**校验（那封信还在、那个人还活着、那个职位没换人），不按全局回合校验；依据变了就作废重排。

**自动暂停**（CK3 式，玩家逐项开关）：要紧的事到案、来信、请见、家中生死、战事、期限将至、离上次推演已久。

### 12.4 推演结算做什么

1. **收口**：时钟停在当日；后台任务里推演要用的等它做完，其余作废、推演后重排（沿用回合后任务队列的等待与脱离）。
2. **世界层推演**：这段时日天下发生了什么（13.2 节）。输入是这段时间的确定性事件日志（按显著度压缩）、玩家的全部行动、NPC 的要紧动作；提示词写明起止日期与天数；写回照旧，AI 的说法只算声明，经写口落账。
3. **视角层推演**：按玩家的身份，把结果滤成他看得见的东西（13.2 节）。
4. **史记、实录**按这段时日写。
5. **新事与来文排进时间线**：AI 生事、奏疏、来信不再一次全摆上案头，而是按发件人所在地算好路程，带上到达日期排进时间线，到日子才到。
6. **推演后后台**：记忆回写、记忆合成、压缩，照现在的回合后任务跑。
7. **存档**：推演后自动存一次。绍宋手存一次约 25 秒，所以不每节存；每节只在内存里留快照，供回滚。

没走满的那一节不补跑，走满时照常跑。

### 12.5 时段的长短

- **不设下限**（同志 09-30 拍）：任何时候都能推演，同一节里也能推几次。推演键旁显示「距上次推演 N 日」和本局已用的调用数，不拦。
  - 代价一：AI 各步现有的「一回合一次」防重复标记（势力调度、回合后记忆任务、认知回写、边患、NPC 深度推演的「五回合未更新」等）按回合数记，同一节里第二次推演会被它们误跳。这些标记改用**推演序号**，放进时1。
  - 代价二：「本段」不能再按节序界定，同一节里两次推演分不开。改按**推演序号与日序**：上次推演之后发生的算本段；玩家行动（诏令、批复、问对、书信、朝议）和事件记录补记日序。
  - 同一节里多次推演，确定性的东西不补跑也不重跑，只在走满一节时跑。
- **提醒**：满三节提示「宜推演」〔初值〕。
- **最长 180 日**〔初值〕：满了时钟自动停，须推演才能继续。时段太长，一次推演讲不清，提示词预算也兜不住。
- 提示词里的「本回合」「一月」改成「这 N 日（某年某月某日至某年某月某日）」；各处 `turn === GM.turn` 的「本回合」筛选改用「本段」助手；AI 写回的增减上限按天数折算。

### 12.6 调速与暂停

- 一速每 2 秒一日，二速每秒一日，三速每秒三日〔初值〕。
- 暂停时可以查、可以看、可以拟稿（工具零代价）；处置、公文、私书、行止暂停时也能下，下了就落账，在途时间从当日算起。

### 12.7 AI 调用怎么排

| 时点 | 调用（现名） |
|---|---|
| 推演·世界层 | sc0 局势分析（完整深度）、sc05 因果回顾、sc1 主推演（含补救、诏令补录）、sc1c 势力与阴谋、sc15 或 sc15n NPC、sc16 势力与 sc18 军事（完整深度）、sc17 财政（缺省跳过）、sc_audit 审查、sc19 新实体（有候选才调）、sc07 NPC 认知 |
| 推演·视角层 | sc1q 对话承诺、sc1b 书信人际、sc1d 史记时政、sc2 正文（或三段叙事）、sc27 叙事审查、史实核对（历史模式） |
| 推演后后台 | sc_memwrite 记忆回写、sc25c 记忆合成两次、sc28 世界快照（缺省并入）、记忆管家与压缩、每 5 节与每 30 节的记忆任务、诏令督查 |
| 两次推演之间·后台 | 势力调度、NPC 自主决断（每节至多 3 次）、问对、常朝、朝议、私书回信、票拟、来文正文、第一层公事批 |
| 按条件 | 边患、悬朝、党派推演、官制章程、事件裁决、终局评价 |

- **每次推演**的调用数与现在每回合的主链相同（标准 14、完整 17～18），只是多久推一次由玩家定。天启每 60 日推一次，主链调用约为现在的一半；晚唐每 30 日推一次，约为现在的三分之一。
- **两次推演之间**的后台调用按日计，每 30 日合计至多 16 次〔初值〕，超出的排队顺延；这与现在天启每回合的势力调度加 NPC 自主（至多约 13 次）相当。

### 12.8 旧界面怎么过

旧界面的「过回合」＝ **节首 → 推演结算 → 节尾 → 来文**。这正是现在一回合的顺序（先征收、再 AI 写回、再系统步、最后奏疏），行为与现在一致。所以引擎可以先改，旧界面照常玩；新前端再做时钟、调速、推演键、自动暂停设置和在途时间线。

### 12.9 存档

- 新增：绝对日序、推演序号、上次推演的日期与节序、时间线队列（预定到达的来文、在途的人与文书、后台任务的待办与已得结果）。
- 读档时后台待办重新排队；已得的结果随档保存，不重算。

### 12.10 本稿里「每回合」的数改成什么

时1 之前（第十七章）一律照旧按回合算；时2 起按下表。

| 原来 | 改为 |
|---|---|
| 案头每回合浮上至多 5 件（3.2 节） | 案头同时待拍板至多 5 件；满了再来新事，就把显著度最低的一件照惯例办掉，并知会玩家 |
| AI 生事每回合入册至多 3 件（2.1 节） | 每 30 日至多 3 件，按推演覆盖的日数折算，一次推演至多 9 件 |
| 第一层每回合至多 8 人、1～2 次调用（5.6、14.7 节） | 后台按到期成批：每 30 日至多 8 人次、2 次调用；推演前把已到期的一并跑掉 |
| 精力每回合回满（9.2 节） | 每日回复上限的 1/30〔初值〕，满则止 |
| 显著度「紧迫」按剩余回合数（3.2 节） | 按剩余日数折成节数 |
| 结案两回合后压进政绩账（16.3 节） | 结案满 60 日后 |
| 文书在一回合里走到哪站（4.6 节） | 文书逐日走，到站即处置；到玩家那一站就停，等玩家批 |
| 所有处置在回合结算开头定稿（14.7 节） | 在节首定稿；玩家与第一层的处置随下随记，第二、三层在节首成批算 |

## 十三、过回合按身份重塑

### 13.1 现状：身份是一整套提示词契约

现在的回合推演是给皇帝过的，而且不是换几个称谓就能改（附录二「最难拆的五处」第一条）：

- **主推演 sc1**：提示词规定「君主本回合颁布正式政令」「玩家私人行动」「君主对 NPC 的意志」，要求用陛下、朕、皇帝叙事；主角取自 `playerInfo.characterName`。
- **sc1q**：输出字段就叫「皇帝采纳」（`adopted_by_emperor`）。
- **sc1b**：玩家以君主身份收信。
- **sc1d 史记时政**：以君主为纲，主角状态取自 `P.playerInfo`。
- **正文 sc2**：主角就是君主。
- **史实核对、终局评价**：直接写「皇帝时期」「这位君主的功过」。
- **其他**：奏疏成批送到御前；常朝、朝议由玩家主持；鸿雁的发信人写死「玩家」、发信地写死京师；勤政与否按皇帝判。

换身份要重定三件事：**看得见什么、能下什么令、叙事以谁为主角。**

### 13.2 两层推演

- **世界层**（身份中立）：这段时日里天下发生了什么，朝廷、各地、各势力、各人物做了什么。
  - 皇帝是世界里的一个人。玩家是皇帝时，皇帝的所为就是玩家的诏令、批复、行止；不是时，皇帝是 NPC，他的诏令由第一层 AI 批按分派顶端的案头产生（11.6 节）。
  - 叙述不以「陛下」为中心，按事发地与当事人记。
- **视角层**（按身份）：把世界层的结果滤成视角人物看得见、够得着的东西（9.3 节视野）。
  - 内容：他案头的事、上下来文、来信、传闻、邸报、请见。
  - 叙事用他的位置与口吻：朕、本部堂、本府、本县、生员。

世界层写多细，按离视角人物的远近分：他的辖区、上下级、家、交游写细，远处只写大势。皇帝的「近处」就是朝廷与天下大势，所以皇帝局的世界层和现在差不多细。

### 13.3 各次调用归哪层

| 层 | 调用 | 要改的 |
|---|---|---|
| 世界层 | sc0、sc05、sc1、sc1c、sc15（sc15n）、sc16、sc17、sc18、sc_audit、sc19、sc07；按条件的边患、悬朝、党派、官制章程 | sc1 拆出视角段；「君主本回合政令」改成「朝廷本段诏令」加「视角人物本段所为」；玩家势力改用视角人物所属 |
| 视角层 | sc1q、sc1b、sc1d 的时政部分、sc2、sc27、奏疏与来文生成、票拟（只在皇帝与票拟之职） | 「皇帝采纳」改「视角人物采纳」；收信人、主角、口吻按身份；皇帝局的史记仍是国史，非皇帝局另写本人年谱 |
| 实时后台 | 问对、常朝、朝议、私书回信、第一层公事批、势力与 NPC 自主 | 朝会主持人按身份与在朝与否 |

### 13.4 推演之后看到什么

| 身份 | 推演后的主界面 |
|---|---|
| 皇帝 | 御案：题本（带票拟）、奏疏、廷议、候见 |
| 官员 | 公案：上司札付、属下申文、同僚咨文、案头的事、邸报 |
| 不当官 | 书案：家事、乡事、来信、传闻、告示 |

### 13.5 皇帝是 NPC 时的朝会

常朝、廷议不再以玩家为主持。玩家是朝官时作为与议者出席，可以发言、附议、具疏；不在朝，就只从邸报与来信得知结果。

### 13.6 提示词按身份分档

- **先做「皇帝」一档**：把现有提示词改成按身份档取词，皇帝档渲染出来要**与现状逐字一致**。做法是金样对照：用天启首回合的固定夹具，把 sc1、sc1q、sc1b、sc1d、sc2 的提示词在改造前后各渲染一遍，逐字比对。
- **再加官员、不当官两档。**
- **称谓**（陛下、皇帝、天子、朕……）改由身份词表给，棘轮守卫禁止新增写死。
- 朝议的提示词量最大，放最后。

## 十四、第一刀：钱粮竖切

### 14.1 这一刀要达到什么

玩家仍是皇帝。做完之后应该看得出来：

- 户部、各道巡抚、各府的官员真的在「办」钱粮：谁严催、谁宽限、谁截留、谁粉饰，都有记录，结果各不相同。
- 奏销、蠲缓请求、加派复命经分派送到御前，出现在现有奏疏界面里。
- 下诏加派不再是「只扣民心、不进银子」，而是变成下达各级的公事，由人去执行（现状见附录「顺带发现」第 1 条）。

这一刀**不做**：新界面（前端正在重做）、刑名等其他领域、视角人物附身。

### 14.2 数据现实

勘察结论（附录 A、B 节）决定了这一刀怎么切：

- **三部剧本走两种财政账。** 天启、绍宋走旧账（没有公库账户，一回合 30 天）；晚唐走统一账（`tm-fiscal-ledger/2` 加公库 `tm-public-treasury/2`，一回合 10 天）。
- **没有征期。** 年税按天数摊到每个回合，每回合结一次；代码里没有开征、奏销、考成期限这些实体。
- **账在叶子上。** 府州叶子有实征率 `compliance`、腐败、钱粮分账、叶库；府以上（省道）没有物理账户，晚唐只有按道合计的只读视图和官署账户。
- **地方官多是「一职多员额」的无名席位**（天启 32 职 352 席、绍宋 76 职 695 席），没有逐府的席位与辖区；省道主官靠行政树省节点的 `governorOffice` 反查（数据线 09-28 已补齐三部）；只有晚唐的职位带 id、`regionId`（治所州）和公库绑定。
- **现在官员影响钱粮的四条路**：履职度改实征率（默认开）、权限门（只管 AI 写的税类收入条目）、省道主官效果（改腐败和政令执行率）、旧账里截留的一半自动进主官私财。
- **Agent 模式可能不征正税。** 全库唯一的征收调用在 LLM 模式的主推演里；行动账的延期提交也只挂在 LLM 模式的写回上（读码推断，待实测）。

据此，这一刀**先在天启跑通**（旗舰剧本、旧账），再适配晚唐（统一账）和绍宋（同为旧账，主要是数据）。

### 14.3 征期

给朝代包加一张征期表，只定期限，不改税怎么算（现有按天摊的征收照旧）。下面是明制的举例：

```js
revenueCalendar: [
  { key: 'summer', label: '夏税', open: { month: 3 }, due: { month: 8 } },
  { key: 'autumn', label: '秋粮', open: { month: 9 }, due: { month: 2, nextYear: true } }
]
```

- 一期的「应征」= 这一期内各回合征收算出的应征之和；「实征」同理。事层只读这两个累计数，不自己算税。
- 剧本没配征期时，缺省「每六个月一期」。唐的两税、宋的夏税秋苗、明的夏税秋粮都是两期，朝代包各配各的名字和月份。

### 14.4 钱粮事类

| 事类 | 何时生 | 主办 | 上呈到哪 |
|---|---|---|---|
| **开征** | 每期开始 | 府州（无名席位的，并入省道一件） | 定本期征收方针；一般到府为止 |
| **催科** | 期中累计实征落后目标一成半以上〔初值〕 | 同上 | 可请展限，上呈省道 |
| **解运** | 每期结束前 | 省道主官 | 截留、迟解须上呈户部 |
| **蠲缓** | 灾伤（现有在册天灾）、民心过低 | 府州 | 请蠲须一路上呈元首 |
| **奏销** | 每年年终 | 省道主官具奏，户部汇总 | 元首 |
| **加派** | 元首诏令或户部题请 | 户部分派到各道，各道分派到各府 | 执行完复命 |
| **交代** | 具名主办换人 | 新任 | 揭报前任须上呈 |
| **优免诡寄** | 叶子兼并田亩高或徭役里诡寄丁多 | 府州 | 清查大户须上呈省道 |

前五类先做（甲2），后三类在甲4补齐。

**钱粮流程表**（4.7 节「流程即权责」的第一份；方括号里是这一站要握的权，抽象键见 4.5 节与九权；站名用明制举例，实际由剧本官制按权与辖区分派）：

| 事类 | 流程 | 考成落在谁身上 |
|---|---|---|
| 开征 | 府州〔征税〕主办，定本期方针；越出权限的处置（如清查大户）报省道〔征税〕批准；监察〔监察〕知会 | 府州：限内完欠 |
| 催科 | 府州〔征税〕主办；请展限时省道〔征税〕批准 | 府州：完欠；省道：展限是否得当 |
| 解运 | 省道〔征税〕主办：如数、迟解、截留；户部〔征税〕验收；截留、迟解超额度时户部批准，大额再报元首〔批〕 | 省道：起解如数及时 |
| 蠲缓 | 府州〔征税〕转详，或在权限内自行缓征，或压下；省道〔征税〕勘灾核转；户部〔征税〕覆议；收呈〔收呈〕；票拟〔票拟〕；元首〔批〕；封驳、抄发〔封驳、抄发〕；户部照办，写蠲免条目 | 府州：报灾是否属实；省道：勘灾是否属实 |
| 奏销 | 省道〔征税〕具奏：如实、粉饰、揭报下属；户部〔征税〕汇核：照准、核驳、题参；收呈、票拟、元首批；科道〔监察〕知会 | 省道：奏销属实；户部：核驳是否得当 |
| 加派 | 元首〔批〕下诏；封驳、抄发；户部〔征税〕分派到道；省道〔征税〕分派到府；府州〔征税〕执行；复命逆着这条链往上走 | 各级：分派是否如额、复命是否属实 |
| 交代 | 新任〔征税〕主办：照收、揭报、分赔、弥缝；上一级核；揭报时科道〔监察〕知会 | 新任：是否揭报；前任：亏空 |
| 优免诡寄 | 府州〔征税〕主办：清查、默许、与士绅议；清查大户须省道〔征税〕批准；士绅是案外利害人；巡按〔监察〕知会 | 府州：清出多少；巡按：是否失察 |

在天启官制里，这些站大体落在知府、巡抚、户部尚书、通政使、内阁、皇帝、六科、都察院与巡按身上——这就是他们在钱粮上的权责，也就是他们各自的玩法。改制时把其中某一站移走（比如让巡抚直接奏销、不经布政使），流程表跟着变，谁得谁失一目了然。

**无名席位怎么办。** 天启三百多个府州，不能每期生三百多件事。规则是：

- 有具名主办的府州、以及本期有异常（灾伤、亏空、大欠）的府州，各生一件。
- 其余府州并成**省道一件**，送到省道主官案头：他定一个全道方针，各府无名官员照此方针、按惯例办（第三层）。方针对远处各府的作用，沿用省道二期现成的「按距首府路程衰减」。
- 这样省道主官第一次有了真杠杆，正好接上省道二期「让地方大员真正起作用」。

### 14.5 处置与落账

**原则：事层不自己算税入。** 正税每回合只在征收（`CascadeTax.collect`）里入账一次；事层只做两件事——在征收之前改本期的征收参数，或者经带回执的转账口动钱。

处置落账经一个**钱粮写口适配层**，分旧账、统一账两个后端：

| 处置要改的 | 旧账（天启、绍宋） | 统一账（晚唐） |
|---|---|---|
| 征收力度 | 本期实征率修正 | 本期实征率修正 |
| 截留 | 截留份额；去向（胥吏、主官、豪强）按处置分，取代现在「一半进主官私财」 | `skimmingRate` 与现有胥吏/主官/豪强三份拆分 |
| 蠲免、缓征、加派 | 税政条目（`TaxPolicy`，带起止日与回执，两账都读） | 同左；另可用税目覆盖 |
| 清丈、清查诡寄 | 叶子上的清丈触发（现有） | 同左 |
| 挪用、补解、补亏空、追赃 | 国库加减的现有函数 | 公库 `transfer`、挂债、还债、追赃 |

实征率修正**不直接改叶子的 `compliance` 字段**，而是写进一本「处置修正」账，征收读 `compliance` 的两处各加一行读它。这样事层撤掉就零残留，也不会和履职度、改革兜底抢同一个字段。

**开征方针**（一期有效）〔初值，影子运行校准〕：

| 处置 | 征收 | 侵渔 | 民心（本地） | 士绅 | 其他 |
|---|---|---|---|---|---|
| 依例 | 0 | 衙门胥吏风气 | 0 | 0 | — |
| 严催 | +0.08 | +0.02 | −2 | −1 | 本地民心 <40 时有激变之虞 |
| 宽限 | −0.08 | 0 | +2 | 0 | 欠额带到下一期（带征） |
| 摊于小户、优免大户 | +0.03 | 0 | −3 | +3 | 常见做法，把柄很轻 |
| 清查诡寄（门槛 60） | 下一次征收时触发清丈 | 0 | +1 | −5 | 士绅来信说情；耗精力 |
| 包揽于胥吏或士绅 | +0.05 | +0.08 | −1 | +2 | 留下把柄 |

**解运**（省道，一期）：如数起解；迟解（本期起运压到下期，考成扣分）；截留充饷（转去偿付本地欠饷，接现有欠饷账）；截留私用（进主官私财，留把柄）。

**奏销**（年终）：省道主官具奏时选「如实」「粉饰」（报完多于实完）「揭报下属」；户部汇总时选「照准」「核驳」（看清度决定能不能看出假）「题参」（把粉饰者参上去）。元首看到的财政读数改读奏销里的**呈报数**，接奏报失真层；巡按、查账是揭真门路——这补上了现在财政没有任何揭真通道的缺口。

**蠲缓**：府州可「转详请蠲」（一路上呈，元首准了才写蠲免条目）、「自行缓征」（在权限额度内，本期少征、下期带征）、「压下不报」（民心续降，被揭出来要担责）。沿途省道「勘灾」可以如实、夸大或压低，户部覆议可以准、部分准或驳。

**加派**：诏令加派改为生成加派事，逐级分派；每一级选「照派」「摊于大户」「摊于小户」「缓派」「抗疏」。落账是按分摊结果写税政条目——**加派从此真的进银子**，代价按怎么摊的落在不同人身上。

**交代**：新任可「照收」「揭报前任」（前任政绩账记亏空、两人结怨）、「分赔」（挂债，前任私财偿付）、「代为弥缝」（亏空转到自己名下，胥吏手里多一份把柄）。

**优免诡寄**：主办可「清查」（清丈触发，士绅反弹）、「默许」、「与士绅议」（部分清出）。这件事的另一侧，就是将来不当官的士绅玩家（第十章）。

### 14.6 考成

- 每期每个主办：限内完欠率 = 本期实征 ÷ 本期应征（扣掉已准的蠲缓）。
- 每期每个省道：起解是否如数、是否及时。
- 每年：奏销是否属实（被揭出之后才算）。
- 这一刀把结果写进政绩账，并把职权舆图喂给 AI 的履职读数改为由政绩账算；考满、京察改读政绩账放在阶段乙。

### 14.7 谁来办、何时定稿

**三层分工：**

- **第三层**：无名席位按省道方针依例。
- **第二层**：具名的知府、布政使等，按性情规则打分（5.6 节）。现有代码里**没有任何「替人物照惯例决断」的确定性兜底**——没有 API key 时 NPC 决断整个停摆（附录 D 节）——所以第二层打分器要新建；原料是 8D 性格、五常、野心、忠诚、压力，以及现有一套休眠的候选打分公式。
- **第一层**：户部尚书、各省道主官等要员，每回合显著度最高的至多 8 人〔初值〕由 AI 成批决断。每回合 1～2 次调用，在玩家思考期间调度（仿势力回合内调度的做法），计入现有每回合调用预算，不另开口子。

**定稿时点。** 所有处置在回合结算开头（prep 阶段、征收之前）一次定稿：玩家的、第一层在玩家思考期间算好暂存的、第二三层当场算的，一起写进处置修正账，本回合征收即按此。第一层的暂存结果要过世界租约校验（回合、读档代数对得上），对不上或没按时回来，就按第二层兜底。不借用行动账的「延期提交」，因为那条路要晚一回合才落账（附录 D 节）。

**成批提交。** 行动账每执行一次都要深拷贝整份世界、再做一次全局校验（附录 D 节），几百件公事逐件走代价太大。所以：

- 第二、三层的处置按省道成批算好，每回合**一次原子事务**写进处置修正账，每个省道一张回执。
- 第一层的处置，以及凡是要动钱、动人、动文书的处置（截留转账、上呈题本、揭报前任），才逐件走行动账，带可核验的引用。为此行动账的核验表加一种 `matter` 引用，签名白名单加上事的 id 与处置类型。

### 14.8 影子运行，再切换

1. **影子运行**：生事、分派、处置照常，处置修正也算出来，但不写进征收；每回合记下「按处置会征多少」与现有结果的差，用来校准〔初值〕。
2. **切换**：开关打开后处置修正生效，同时退役与之重复的旧效果（15.2 节）：履职度对实征率的作用、旧账截留一半进主官私财、AI 直接写税类收入、改革兜底的全境加成、绕开账本的即时加派开仓借贷。
3. **对账测试**：国库收到的起运，必须等于各件钱粮事结算出的解运之和；截留每一两都有去向；同一笔钱不得在事层和旧效果里各算一次。

### 14.9 验收

- 天启无头跑 24 回合（两年），不接模型（只有第二、三层）：每回合生事数在上限内；零运行时错误；对账逐两相等；每个具名主办都有考成记录；每年奏销送到御前；一道加派诏令能落成税政条目并真的增收；选了粉饰的地方出现呈报与实情之差。
- Agent 模式下同样定稿、征收、对账（先实测现状缺口）。
- 接模型的真机小局（要用 API，时机由同志定）：第一层每回合至多 8 人，输出全部过校验，AI 的说法与回执对得上。
- 之后依次适配晚唐（统一账、带 id 的职位与公库）和绍宋。

## 十八、风险与对策

| 风险 | 对策 |
|---|---|
| 做成公文模拟器，玩家被琐事淹没 | 同时待拍板的事不超过 5 件（12.10 节）；其余照惯例办；幕宾分担；显著度把真正有戏的事挑出来 |
| AI 调用成本与回合耗时 | 公事里只有第一层调 AI，每 30 日至多 2 次、8 人次，计入实时后台预算；没有 API key 时全走第二、三层照样能玩 |
| 逐件走行动账太重 | 行动账每次执行都深拷贝整份世界；第二、三层成批一次提交，只有动钱、动人、动文书的处置逐件走 |
| 存档膨胀 | 行动账的回执与政治来源现在不裁剪；公事自带有界存储，结案满 60 日后压进政绩账；政绩账每任只留摘要与最近若干条；时间线只存未到的来文与未完的待办 |
| 与现有财政结算重复记账 | 先影子运行；钱只从现有写口过；专门的对账测试 |
| 提交时点与 Agent 模式 | 行动账的延期提交晚一回合；Agent 模式可能既不征正税也不提交。公事有自己的定稿点（prep、征收之前），两种模式都挂 |
| 玩家身份写死 | `isPlayer` 约 400 处、`P.playerInfo` 近 400 处（玩法读者已在修缮片3c 改读运行态并加棘轮，余下是开局与剧本级设定）、「玩家」字面量 60 处；外观层、棘轮守卫、分批迁移 |
| 称谓与人设 | 「陛下」605 处、「皇帝」287 处、「天子」114 处……多在提示词和朝议里。这是内容工作：按身份给提示词分档，朝议（11 个文件、约 1.6 万行）放在最后 |
| 旧存档 | 新字段全部登记进存读档；迁移可重跑；所有接管开关默认关 |
| 平衡被打乱 | 现有数值按旧模型调的；影子运行期间校准，再给轻、中、强三档力度 |
| 剧本数据缺口 | 大量州县没有具名官员，走第三层；统属、辖区由代码推缺省；要补的（文书流五权、家族入册、士绅家族）交数据线 |
| 朝代差异 | 代码只用抽象键；事类、处置、征期、家法都放朝代包；先天启、再晚唐、再绍宋 |
| 性能 | 生事数按日封顶；无名席位按省道合并；案头与分派链建索引；节尾耗时逐节记账 |
| 确定性与回放 | 每件事带自己的随机种子；在途的事按旧链走完；AI 输出只作声明 |
| 叙事与机制脱节 | 事的文字只作展示；主推演读的是有类型的处置结果与政绩账 |
| AI 生事刷屏或凭空造数 | 生事闸：类型、数额上下限、利害人在册；无佐证标风闻，须查实才按实结算；按日折算的上限 |
| 提示词就是身份契约，换身份牵一发动全身 | 先做皇帝档，金样逐字对照、零变化；分档逐次迁移；称谓词表加棘轮（13.6 节） |
| AI 写回与系统步本是同一个事务，拆开后先后顺序会变 | 节律自带快照与回滚；AI 结果只在推演时落一次，不在节里重放；旧界面「过回合」按节首、推演、节尾排，与现在同序（12.8 节） |

| 后台 AI 与推演、节律抢着写 | 后台结果按依据对象校验；推演前收口；待办入档、读档重排（12.3、12.9 节） |
| 确定性系统非线性，拆成逐日会改结果 | 节内照现在一次跑，不拆成逐日；只把本来就按日的（在途、期限、到达）放进日层；新旧两种模式影子对比 |
| 存档慢（绍宋手存一次约 25 秒） | 不每节存；推演后存一次；每节只留内存快照 |
| 节尾耗时让实时卡顿 | 节尾跑时停钟、显示月结；单节耗时记账，超出预算列性能债 |
| 推演太勤费钱，太疏讲不清 | 不设下限（同志拍），推演键旁显示距上次推演的日数与本局调用数；满三节提醒、最长 180 日 |
| 后台 AI 跟不上三速 | 在途日数盖住模型延迟；到日子结果还没回来，该件顺延到达（驿路迟滞），不停全局时钟；后台每 30 日至多 16 次，超出排队 |

## 十九、我先定下的小项（实施前逐项回桌）

- 模块与字段命名（16.3 节）。
- 显著度公式、亲办耗费、看清度公式、胥吏风气缺省值、钱粮处置的各项效果（均为〔初值〕，影子运行校准）。
- 第一层每回合至多 8 人、1～2 次调用；时2 起改为每 30 日至多 8 人次、2 次调用。
- 案头每回合浮上至多 5 件；时2 起改为同时待拍板至多 5 件。
- AI 生事每回合入册至多 3 件；时2 起改为每 30 日至多 3 件，一次推演至多 9 件。
- 考满、京察、大计周期沿用现有配置，朝代包可改。
- 诸子均分由家法开关控制，缺省开。
- 门生传衣钵的资格：须与当家人有师生或座主门生关系，在世、成年，且本人不是别家的当家人。
- 公事存储：未结的全留，已结的留两回合（时2 起为 60 日）后压进政绩账。
- 时间：节＝剧本每回合天数，`GM.turn` 按节加一；推演不设下限，满三节提醒，最长 180 日。
- 速度：一速每 2 秒一日，二速每秒一日，三速每秒三日。
- 自动暂停缺省全开（要紧的事到案、来信、请见、家中生死、战事、期限将至、推演提醒），玩家可逐项关。

- 精力每日回复上限的 1/30。
- 推演后自动存档一次；每节只留内存快照。
- 开关：底座 `guanbenMattersEnabled`、钱粮接管 `guanbenRevenueEnabled`、视角人物 `guanbenPerspectiveEnabled`、即时加结算 `realtimeSettlementEnabled`，都默认关，设置里配开关；影子运行校准、同志试玩后再翻。
