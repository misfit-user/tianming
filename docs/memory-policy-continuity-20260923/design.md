# 天命压缩与长期记忆完善方案

日期：2026-09-23。依据：当前本地运行源码及同目录 `probe-results.json`。

本文为开工前诊断与设计；实施结果见 implementation.md。诊断阶段尚未修改游戏运行时。没有访问玩家存档、调用真实模型 API、打包或发布。玩家具体版本与出错存档尚未提供，因此不能把以下机制问题直接等同于该玩家个案的全部原因。

## 1. 核心原则

**仍然生效的政策应当属于当前世界状态；历史记忆负责解释它为何建立、如何变化、产生过什么后果。**

长期规则、未履行承诺、未结束工程、条约、战争目标和人物持续意图，都应有可更新的状态记录。近期原文离开提示词窗口后，这些状态仍然有效，直到明确撤销、替代、到期或条件不再成立。政策的执行率、地方阻力、违法行为和实际成效继续由局势与推演决定。

保留当前已有的长期档案、混合检索、证据治理、人物权限、记忆管家和回合复核，重点补齐它们之间的数据与生命周期契约。Agent 保留已授权的世界修改能力，修改通过现有领域写入接口留下回执，记忆据实际变动更新。

## 2. 当前代码已经复现的问题

以下是具体入口或组件结果，不是整份最终模型请求的捕获，也不是实际模型连续游玩测试。

| 问题 | 执行证据 | 后果 |
|---|---|---|
| 皇命表读取格式不一致 | 真实 `MemTables.editorWrite` 写入数组行；`MemoryEnvelope` 按 `row.content/title` 读取，生成空正文。旧表格注入包含该政策，统一记忆块不包含 | 新旧入口与 Agent 的可见性不一致 |
| 有效政策与人物争抢预算 | 100 人物、24 项有效政策；真实均衡档 3000 tokens、每条 240 字，只输出 1 项政策；6000 tokens 输出 3 项 | “高优先级”“mustKeep”只保护分区，不能保证分区中的政策被保留 |
| 政策条件被截断 | 291 字政策的例外、三年期限位于尾部；140/180/240 字条目限制均漏掉，即使总预算为 12000 tokens | 模型可能记得标题，却错误理解适用范围、期限和例外 |
| 压缩前已经损失内容 | 记忆管家把单条旧记忆截前 200 字；318 字样例的轮休条件未进入压缩请求 | 改进摘要提示词也无法恢复模型没看到的条件 |
| 摘要成功缺少内容覆盖校验 | 合法、非空但完全漏掉政策的模拟摘要仍被应用 | 格式成功会被误当成记忆完整 |
| 常用记忆源未接进长期归档投影 | 管家压缩前调用 `harvest`，但投影器读取 `_aiMemorySummaries`，没有读取默认写手持续写入的 `_aiMemory`；仅由后者承载的合成条目未进入长期库 | 部分材料可能在压缩替换时失去这条归档保障；完整存档可能另有史记副本，需逐源核对 |
| 执行完成与政策效力需要分离 | `_edictTracker.status=completed` 后该条退出有效政策投影；另登记为 `activeEdicts.status=active` 后可见 | 一道“设立常制”的命令可能办结，但建立的规则仍应生效 |
| 历史窗口形成断点 | 实际参数在 32K 档为近 5 回合全文、至第 12 回合摘要；更早依赖其他记忆层。中段诏令还只取每类首条的前 40 字 | 同一回合多条政策与较长政策容易丢掉后半段；与玩家描述的时间点相符，但不是唯一原因 |

控制组：仅有一项正常登记的有效政策时，T1–T50 共 50 个回合编号的编译检查全部保留。因此重点是登记、格式、预算和状态演变，不能简单归因为回合数达到某个阈值。

代码定位：

- `web/tm-memory-tables.js`：皇命表真实列定义与写入形态。
- `web/tm-memory-envelope.js`：政策、表格、摘要和档案投影。
- `web/tm-memory-context-compiler.js`：条目裁剪、coreFacts 排序与区内预算压缩。
- `web/tm-memory-steward.js`：压缩输入、结果检查、归档与替换。
- `web/tm-memory-long-term.js`：采集、类型排除、容量和字符限制。
- `web/tm-endturn-followup.js`：默认记忆写手、皇命候选及普通压缩分支。
- `web/tm-endturn-ai.js`、`web/tm-memory-mode-bridge.js`：普通模式与 Agent 的实际接入。

## 3. 建议的分层结构

```mermaid
flowchart LR
  A[诏书、对话、推演原文] --> B[原文与变更证据库]
  A --> C[政策与事项变动候选]
  C --> D[领域写入与实际回执]
  D --> E[当前有效政策、承诺和事项]
  B --> F[按主题和阶段生成摘要]
  E --> G[本回合必需规则与进度]
  F --> H[相关历史检索]
  B --> H
  G --> I[统一上下文编排]
  H --> I
  I --> J[主推演]
  J --> K[既有 Agent 复核]
  D --> K
  E --> K
  K --> C
```

| 层 | 保存内容 | 更新与淘汰规则 |
|---|---|---|
| 当前世界状态 | 财政、官职、生死、领土、机构、军队等 | 继续由现有领域状态与写入接口负责；历史摘要不直接覆盖 |
| 持续规则与未决事项 | 有效政策、条约、承诺、工程、改革阶段、战争目标 | 状态驱动；年龄只影响历史展示顺序，不能自动判为失效 |
| 人物主观记忆 | 态度、恩怨、信念、恐惧、承诺、已知信息 | 明确主体、对象、来源、置信度及变化；人物误解保留为主观认识 |
| 近期事件证据 | 近期诏书、实录、时政记、对话与实际变更 | 保留具体文本与发生顺序，提供细节和回执 |
| 主题摘要 | 某项改革、战争、财政危机、关系发展的阶段概括 | 从证据生成，带来源和覆盖范围；可失效、重建，不承担现行规则唯一副本 |
| 冷档案与索引 | 更早的原文、旧政策版本、历史结果 | 分块持久化、按需读取；存储容量与单次提示词预算分开管理 |

## 4. 政策生命周期：优先完善现有数据

以现有 `activeEdicts` 及政策领域状态为基础确立统一读取契约，先适配旧数组行、对象行与历史别名，避免再建一个与它们互相竞争的真值表。皇命表和 `_edictTracker` 通过稳定 ID 关联该记录。

至少分开记录两种状态：

- **法令效力**：拟议、有效、暂停、到期、撤销、被替代。
- **执行任务**：待传达、执行中、部分完成、受阻、已办结、失败。

“已完成颁行免税令”可以对应“颁行任务办结、免税政策有效”。一次拨款执行完成后保留结果与凭证，不能因长期记忆而再次拨款。按年拨款、季度考核等周期性义务使用独立周期和履行记录。

建议记录这些字段，具体命名在实施时对齐现有 schema：

| 字段组 | 内容 |
|---|---|
| 身份与版本 | 稳定政策 ID、版本、所属世界/时间线、颁布者 |
| 范围 | 地区、阶层、机构、军队、人物及名称别称 |
| 核心条款 | 行为、金额或比例、单位、资金账户、频率、上限 |
| 条件 | 生效时间、期限、触发条件、终止条件、例外 |
| 当前执行 | 执行者、阶段、覆盖地区、进度、阻力、最近核验 |
| 变化依据 | 原诏与修订来源、替代/撤销关系、实际写入回执 |

未能解析为机械效果的自定义条款保留原文和语义条件，支持 Agent 继续推演，不能因为不属于预定义类型而丢掉。初次登记可复用主推演和现有回合复核；不要求每道诏书新增一次独立模型调用。

## 5. 压缩：保留可以继续推演的事实

### 5.1 压缩前

1. 保存本批输入的稳定 ID、版本和来源索引，确认旧原文确实可重新读取。
2. 从政策、承诺与事项状态生成“不可遗失字段清单”：数值、账户、期限、适用对象、例外、否定、当前阶段和未解问题。
3. 长条目按完整条款分块，保留重叠上下文；替换当前前 150/200/240 字截取。
4. 同一事件的多个来源去重，但保留互相矛盾的证据及各自来源。

### 5.2 压缩方式

先按政策/事项/人物/战争等主题分组，再按发展阶段压缩。优先合并重复叙述，稳定保留“原因 → 决策 → 执行 → 反应 → 当前状态”。新的进展更新对应主题，避免一遍遍把全部历史缩成同一段固定长度文字。

主题摘要携带：覆盖源 ID、时间范围、核心事实、变化点、仍有效条款、未履行事项、争议信息、已明确终止事项，以及未纳入材料的原因。

主题摘要进一步汇成时期概览时，时期概览继续保留向下展开的索引。当前有效规则仍从状态层提供。

### 5.3 压缩后

检查来源是否存在、关键数字与否定是否变化、政策版本是否对应、未决事项是否无依据地办结。确定性检查适合核对数值、ID、时间与字段覆盖；语义争议交给既有 Agent 复核，不扩大容易误判的关键词拦截器。

缺少重要内容时保留原条目或独立事实包，摘要标记为部分完成并后台补做。**沿用已确认的回合规则：有效主推演完成后正常提交，记忆整理失败不回滚该回合。**

所有压缩入口使用同一提交函数：仅替换输入快照对应的记录版本，保留期间新增记录；读档、切世界、换时间线或源记录修订后，过时结果失效。普通 compress、记忆管家、Agent 整理与 L2/L3 应共享此契约。

## 6. 提示词与召回：检查最终真正发出的内容

### 6.1 统一分配预算

将人物现状、当前政策、待办承诺、历史证据和叙事背景分区。人物名单有独立额度，避免其占满政策额度；已在世界快照提供的事实不再完整重复一次。

仍有效政策保留在权威库中。全局约束及与本回合地区、人物、资金、时间命中的规则，优先展开完整关键条款。其余提供可读的紧凑索引和待展开计数。很大的政策集合需要按领域和范围分组，不能承诺有限窗口一次容纳无限条款。

示意：`P07@3｜有效｜江南新垦田｜免田赋三年｜旧田照旧｜禁止追征｜原诏 R19`。裁剪时保留整条约束，不切掉尾部例外。预算依照整个请求分配，不能先在一个子块宣称全部保留，随后又被全局中段截断。

### 6.2 必需规则主动供给，历史细节按需查

触发查询的依据包括：当前诏书和目标地区、受影响阶层与机构、资金账户、期限到点、长期事项阶段变化、对话承诺，以及输出中新出现的行动对象。继续使用现有关键词、向量和关联边检索，统一名称别称、有效时间、来源权限与纠错标记。

对仍有效规则不能完全依赖模型自行想到“要回忆哪项政策”。生成新的行动提案后，再按行动范围检查相关政策是否遗漏，必要时定向补读；最终复核区分遵守、违法、例外、撤销和普通生成错误，并反映实际后果。

### 6.3 最终请求审计

在所有拼接、预算处理、模式转换完成之后、真正发送之前，记录本次使用的政策/证据 ID 与版本、关键条款覆盖、被缩减或未展开原因。日志默认记录元数据和必要摘录，不写 Key 或完整 API 配置。

同一套检查覆盖普通主推演、Agent、问天/天意、NPC 行动与回合复核。各入口可有不同任务预算，但共享事实语义、来源格式及当前政策版本。

## 7. 让既有 Agent 复核闭环

复核读取四份材料：本回合玩家意图、当前有效规则、生成的时政记/实录等原文、实际状态变更与写入回执。

重点判断：旧政策是否被当作不存在；新政策是否已登记；叙事是否宣称执行却没有落账；范围、金额、账户或周期是否错误；撤销与替代是否真的生效；真实的违令、阻力和失败是否有合理记录。

可以修正或主动补充遗漏，但修正要形成新的可追溯回执，并更新相关记忆版本，防止下一轮再召回旧错误。使用现有回合复核和应急补救机制，减少重复模型调用。后台压缩可与独立后续任务并行；供主推演使用的关键检索必须及时完成，不能宣称所有工作都能零耗时并行。

## 8. 持久化、旧档与界面

- 原文、索引和摘要分别管理。近期材料保持热缓存，旧原文分块落盘并按需读取，避免把庞大历史反复复制进每次启动或完整项目快照。
- 现行政策和未决事项不参与普通历史淘汰。容量不足时保留必要事实与来源索引，明确报告可用范围；不能在原文未安全落盘时宣称归档完成。
- 旧档先兼容读取，再后台分批回填。已登记状态优先；从旧诏书和实录推断的长期规则须核对后续撤销及执行结果，无法确定的保留为候选。
- 存档迁移应可取消、断点续做、幂等，并遵守现有 canonical 保存事务和世界/时间线隔离。不得牵连 API 配置或存档目录选择。
- 界面提供“当前有效政策/未决事项”和“本回合实际读取的记忆”；支持查看原文、版本历史、漏读原因，以及明确的纠正、置顶和停用操作。
- 历史召回额度、压缩质量、整理任务成本分别显示。当前政策属于世界状态，额外历史检索是独立设置；不暗中开启额外付费调用，也不把“提高预算”作为唯一修法。

## 9. 建议实施顺序

| 批次 | 范围 | 收口标准 |
|---|---|---|
| 第一批：堵实际漏点 | 皇命表数组/对象规范化；接通 `_aiMemory` 来源；政策与人物分配预算；去掉重要条款固定前缀截断；真实发送前覆盖记录 | 本文探针中的空正文、政策挤占、尾部条件丢失得到修复；保留原有权限与世界隔离 |
| 第二批：政策与事项状态 | 分离法令效力/执行进度；稳定 ID、版本、期限、范围、周期履行与明确终止；打通两种回合模式、问天与复核 | “颁行办结后政策仍有效”“撤销后旧法不再生效”“周期拨款不重复扣”成立 |
| 第三批：统一压缩提交 | 分主题分层摘要、完整输入分块、关键字段覆盖、持久化原文索引、并发版本校验与局部重试 | 连续多次压缩、晚回包、并发追加与读档分叉均不丢新记录、不混旧世界 |
| 第四批：旧档、可见性与长局验收 | 渐进回填、记忆诊断界面、长期剧情/人物验收与相同模型预算的对照 | 玩家能追溯政策从颁布到当前效力；实际模型与客户端长局结果单独报告 |

优先复用已有模块和领域所有者，每批保持独立回归，避免一次重写全部记忆系统。发布仍由仓主单独触发。

## 10. 验收矩阵

### 确定性与合成回放

- 50–100 回合，混入大量无关人物、战争和日常事件，验证早期有效政策持续供给。
- 完成颁行任务后仍维持政策；撤销、到期、局部豁免和替代后使用正确版本。
- 同一道长诏书含多项政策、数值、否定、例外与条件，压缩三轮后逐项核对。
- 国库/内帑/粮储账户分开，年度义务按实际游戏时间到期执行，不按每回合重复扣款。
- 人物更名、换官、死亡和执行者更换；承诺、关系变化和主观误解各自保留正确归属。
- NPC 故意不遵守政策应成为有依据的剧情和后果，不被错误当成“系统忘记”或无条件纠正。
- 不同上下文窗口、无向量模型、检索失败、摘要失败、部分输出和真实预算溢出。
- 压缩期间追加记忆、快速进入下一回合、切档、分叉、保存失败和重启恢复。
- 普通模式、Agent、问天/天意、应急补救和复核共享相同政策版本。

### 实际模型与客户端

在同一模型、同一 API 配置、相同游戏输入和成本约束下进行旧/新对照。分别记录：源记录保留率、关键规则注入覆盖、原文可解析率、模型引用与遵从情况、实际变更准确率、每轮输入/输出 tokens、额外调用数、前台耗时和后台积压。

对声明的受测负载，确定性目标是：应注入的关键条款零静默遗漏、被撤销规则零误当现行、引用原文可定位、没有重复履约。模型表现报告实际通过率和错误样例，不以单元测试通过承诺“永不遗忘”。主推演有效完成后，记忆维护失败应可恢复并保持回合提交。
