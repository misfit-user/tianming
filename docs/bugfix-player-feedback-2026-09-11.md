## 已完成的游戏端修复

| 问题 | 证据与处理 |
| --- | --- |
| 部队名册只能翻找 | 增加名称、统帅、驻地、兵种、ID 搜索；空格分词采用同时匹配。先过滤完整名册，再渲染，能找到第 36 行之后的部队。保留全军汇总、原有详情入口和朝代中立界面。 |
| 搜索与界面状态 | 输入不重建整块抽屉，保留焦点与中文组合输入；清除按钮恢复全表；旧异步列表不能覆盖新结果；换存档清空旧世界查询，同一世界重开保留查询。 |
| 4K 上下文缓存串用 | 同步读取上下文和输出上限时，校验探测缓存的“模型名 + API 地址”身份。新模型只探得上下文时，不给旧输出上限盖新身份。手动设置仍优先，不擅自增大玩家填写的容量。 |
| 收到响应头后正文失去超时保护 | 保留原有请求期限，用同一期限覆盖响应头与完整 JSON 正文；支持取消退避等待；对不响应 abort 的正文读取器也拒绝迟到结果。没有缩短既定超时或删减请求正文。 |
| 多层重复重试 | 底层重试用尽后的明确超时、取消、4xx 和硬上下文错误，不再被智能调用层/子调用包装器原样重跑。可恢复网络错误仍有原有有界重试。 |
| 主推演失败被伪装成继续完成 | 必需系统前缀已不可能装入配置窗口时，提前终止主推演；最终完整 schema/正文预算闸仍保留。逃出恢复边界的错误交回原有 core 事务回滚，不写成“失败叙事”继续最终化。 |
| 校准误判“无 JSON” | 党派/阶层校准启用现有完整正文契约：合法分段文本可正常解析，思考块不混入结果；拒答、纯思考、截断结果不能作为成功修改。请求内容、输出额度不变。 |
| 字体 CSS 被 CSP 拦截 | 顶部栏不再注入 jsdelivr 字体样式，改用 `styles.css` 中的同款本地字体名称。没有放宽 CSP。 |

保存前 `sc25c` 等关键记忆任务的失败门禁、旧世界结果丢弃、最终写回校验均未删除。没有降低 AI 深度、输出量、验证质量，也没有用随机结果代替 AI。

## 没有据截图直接归咎 API 的部分

- `AbortError` 和 `no JSON` 本身不能证明中转故障：本轮已修复游戏端期限、重试、正文契约和错误传播缺口。未拿到真实响应，无法声称这些修复已解决该玩家全部失败。
- 真正返回空正文、非 JSON、截断结果或服务端错误，仍应明确失败并保留可靠恢复边界，不能为了显示成功而降质写回。
- 缺少本地语义模型时，当前检索入口和回合索引钩子均有 `modelReady` 门控，不等待缺失模型阻塞 SC1；没有强制下载远端模型或关掉玩家功能设置。
- 第三方 `sw.js` 的 206 缓存错误确实存在，但脚本只拦截 GET，不能把 AI POST 中断全部归因于它。该脚本不在本仓，处理方案单列于 [第三方站点修复方案](handoff-third-party-site-2026-09-11.md)。
