# 诏令效力：办结不等于废止（2026-09-24）

## 要解决的问题

玩家反映「十几回合后 AI 忘了政策」。病根在诏令管线：玩家诏令存在 `GM._edictTracker`，被当成一件会办完的任务。颁行办结、报了 completed 之后，它会从下面这些地方一起消失：

- 主推演提示词的「跨回合持续诏令」段（`tm-endturn-ai.js`）：只收执行中、受阻、在途的诏令，最多 12 条，每条截 80 字；
- 记忆信封与检索：按「未了结」过滤；
- 回合准备：已办结的诏令两年后整条删除；
- agent 模式登记诏令时，正文只存前 400 字。

另外，玩家钉在皇命表（`MemTables.imperialEdict`）里的条目是数组行，统一记忆块却按对象字段读，读出来是空的。上下文编译器还会把现行规则按单条 180–240 字截断，排在人物名单之后，被挤出预算。

Codex 此前的方案（`activeEdicts` 真值表、原文档案、冷存储、主题账本）是从记忆压缩这一侧去修，主通道没有改动，已由仓主叫停。第一轮回写的文件已还原。

## 做法：在诏令本身上把「效力」与「执行」分开

每条诏令新增 `efficacy` 字段，与执行状态 `status` 分开记：

| efficacy.state | 含义 | 是否现行 |
|---|---|---|
| （无，即未判定） | AI 尚未判定 | 是，宁可多带，不可静默丢 |
| standing | 常制 | 是 |
| term | 有期（`untilTurn` 为最后有效回合） | 期满前是 |
| one_off | 一次性，办完即了 | 否 |
| expired / revoked / superseded | 已到期、已撤销、被替代 | 否 |

下面几类条目不走 AI 判定，直接视为一次性：
- 系统确定性生成的条目：缺员通告、官制面板任命、弹劾、官制树任命、赈济试点；
- 执行状态已作废的条目：cancelled、revoked、rejected、aborted、withdrawn，这类视为已撤销。

### 宪法栏（`web/tm-edict-efficacy.js`，只管容器与守卫）
- `stateOf` / `isCurrent` / `current`：统一读口。
- `tick`：每回合在回合准备中调用。它补齐缺失的编号（鸿雁登记的诏令原本没有 id），并把期满的有期诏令转为已到期。
- `prune`：替代回合准备里原来的清理规则，新增一条「仍现行的不删」。
- `promptSection`：生成【现行诏制】提示词段，带全文，默认上限 6000 字；超出的诏令只列要点并注明未展开，每道现行诏令都会列出。
- `feedbackGuide`：只在有未判定的诏令时，请 AI 判定效力。旧档积压的旧诏每回合只点名最早 8 道。

### 演绎栏（AI 判定，`judge` 是唯一落账口）
- 主推演：`edict_feedback` 条目可带 `efficacy`、`until`、`digest`、`revokes`、`supersedes`。只有按编号或正文精确匹配到的反馈才会被采纳；按「本回合任意一条待办」兜底匹配的不采纳，防止判到别的诏令上。
- agent 模式：新增写工具 `judge_edict`，与主推演走同一个 `judge`。
- 撤销与替代只能由新下的诏令发起（本回合或上一回合登记的诏令），被废的须更早且仍现行。已到期、已撤销、被替代的诏令不接受改判，要恢复只能另下新诏。
- 期限解析：「三年」「十个月」「半年」「至T40」「第25回合」或回合数，按每回合天数换算。解析不了的保留原文，不自动到期，由 AI 日后报 expired。

### 各通道接入
- 主推演：在【跨回合持续诏令】之后加【现行诏制】和判定说明；本回合诏令两段都加 `#id=`；玩家诏令原文段标出 `edictId`。
- agent 模式：基线上下文加入【现行诏制】与 `judge_edict` 判定说明，不受默认关闭的诏令督查开关限制。
- 记忆信封与检索：仍现行的诏令照样投影为现行法令，状态记为 active。
- 皇命表：数组行统一转成对象再读（`MemoryEnvelope.imperialEdictRecord`），隐藏列为真的条目只给系统推演看。
- 上下文编译器：现行法令（诏令、皇命、承诺）不按单条字数截断，并整体排在人物名单等事实之前。

## 验证

- `web/scripts/smoke-edict-efficacy.js`：19 项。其中一项复现了诊断场景（100 个人物、24 道现行诏令、3000 tokens）。同一探针对照结果：
  - 进入记忆上下文的诏令：改动前 1 道，改动后 24 道；
  - 已办结的诏令：改动前 0 道，改动后 12 道全部进入；
  - 长条款尾部的例外：改动前丢失，改动后保留；
  - 皇命表条目：改动前不可见，改动后可见。
- 13 项架构守卫、官方剧本对账、跨发布契约、热更构建闸、全量 smoke 结果见提交说明。

## 边界与未做

- **没有用真实模型跑过**。AI 是否按要求判定效力、是否据【现行诏制】行事，需要用真实模型跑一小局验证，要用 API，由仓主决定时机。
- 旧档第一次接入时，最近两年内已办结的诏令会以「未判定」重新出现在【现行诏制】里，逐回合由 AI 判定。这是有意的：它们可能正是被遗忘的常制。
- agent 模式若始终不调用 `judge_edict`，一次性诏令会一直以「未判定」挂着。篇幅由预算和要点压缩兜住，不会丢失，但会占位。
- 以下几处未改动：
  - 【跨回合持续诏令】段的 80 字、12 条上限，以及诏令督查的 24 回合上限。它们只管执行追报，条文已改由【现行诏制】提供。
  - 国策 `GM.customPolicies` 的 30 条上限（超过会挤掉最早的国策）。它是剧本配置的命名国策，是另一套机制，另议。
  - `_aiMemory` 进入长期记忆收集口。这属于记忆系统本身；Codex 那种做法每次编译要多投影 200 条，另议。
- 界面这轮不做。以后单独设计只读的「典章」视图，界面上不能改效力。
