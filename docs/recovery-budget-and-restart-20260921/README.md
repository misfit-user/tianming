# 固定回合复核、应急预算与财政漏扣修复

2026-09-21，修改已同步到本机源码。未打包、推送或发布。**实机过回合与重新读档验收仍待用户重开游戏。**

本轮补充已完成：完整原文送审、后续新结果补核、实际前后值与数据差异、Agent 修改后再核验。最新结果为 62 组回归、29 个专项用例通过；详见 [原文与修改后核验补充](original-evidence-review.md)。以下保留前一轮修复范围及记录。

## 本次行为

- 每个 AI 回合固定由 Agent 复核，检验器没有警告也会执行。检查误判、诏令实际执行、状态一致性和检验器未覆盖的遗漏；可通过现有游戏写入口修正或补充人物、军务、财赋、外交、区划、社会与回合文本。
- 普通推演先完成主写回，再启动只读复核，与后续推演并行。所有候选在后续推演结束后统一执行；改动对象或引用证据发生冲突时，在同一次预算内重新核查。完整 Agent 模式也接入固定复核，但在其主流程完成后运行，不承诺零额外等待。
- 真正的主写回失败可交给 Agent 修订失败批次，再经原子应用器重试。实际写入失败、资金不足等不能靠一句“通过”放行；任一修正失败会回滚整组修改。最终提交要求固定复核成功回执。
- 检验器的叙事判断和自身异常会保留为复核证据。财政实际写入错误仍拒绝提交；财政关键词扫描在固定复核路径上不再擅自向国库补账。
- 取消、切档、接口切换或回合结束后，旧候选不得继续写入。复核任务、快照和进行中的 Promise 不写进存档。

## 内帑与帑廪

确认了两个独立问题：普通拨款诏令曾丢失显式账户，默认从国库支付；主写回使用 narrative 字段，而财政扫描没有读取该字段，可能漏过正文中已经声称完成的支出。现已补上账户识别和正文入口，并将实际付款回执传给后续推演，避免重复扣款。

固定复核会核查“诏令已花钱，但内帑和国库都未扣”的情况；补款必须使用正式财政写入口。回归覆盖分别扣内帑、扣国库、双方均未扣时补款、余额/账本镜像一致、序列化重载后不回弹、余额不足不换账户，以及已付回执不被重复记账。

旧玩家没有提供原诏书或存档，因此以上是当前代码的可复现问题与修复范围，不能反推旧案例一定由同一个触发点造成。

## 设置

“回合复核与应急推演”中可调整调用、候选修订、工具步骤、Token 和等待预算，取消此前固定的 20/10/80 等人为上限。仅保留有效正整数检查，等待 0 表示不设时限。读取旧存档保留最新预算偏好。

固定复核每回合执行；“失败后的应急策略”开关仅控制原先的失败后恢复。复核和应急各使用设置中的每次预算，冲突重核计入本次预算。之前已在真实设置页面验证 100 次调用与 2000000 Token 的保存/重开/读档保留，并恢复用户原先的 7 次调用、4 次候选、19 步、48000 Token、等待 0。
