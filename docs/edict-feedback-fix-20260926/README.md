已把玩家诏书接入完整的“输入 → AI 推演 → 结构化写回 → 逐道回报 → 史记归档”链路。完整颁行的诏书保留原有稳定 ID；分类诏书、重复提交、未知 ID、后台补正和读档后的反馈都按同一份 tracker 处理，不再因为只写入 `edicts.decree` 而在期末静默消失。

## 实际数据写回

- 财政沿既有财政账本落账，记录申请、实付、欠付和短缺；重复现金字段不会再次扣款。
- 内帑/国库、民心、吏治、皇威、皇权和剧本 `vars` 使用实际领域入口与剧本定义的范围，不创建影子变量。
- 阶层与党派按真实实体 ID/名称精确匹配，记录满意度、影响力等字段的 before/after；同一字段被多道诏书触及时，净变化不会整批重复归因。
- 每项效果保留 `edictId`、`effectId`、领域、执行人、状态、before/after、实际值和短缺；阻塞、部分执行、未核实和在途状态不会伪装成成功。

此前报告中的两个相关问题也在同一套真实数据口径上复验：右栏财政优先读取已交割账本，旧的全局标量和重复税项不会把预计数冒充本期实收；阶层满意度、党派影响力和本回合预算按实际 delta、反向变动和上下限结算，不从静态诉求文字臆造变化。

## 史记分卷

- **实录**：按回合记录已确认的事实与结果。
- **时政记**：记录执行过程、因果、执行人、阻碍和奏报/探报/传闻来源。
- **后人戏说**：把同一组已落库事实转成民间视角的场景、对话和人物感受。

三卷均在主写回和结算完成后取事实；后台效力审计按原回合回填，不能把晚到的结果串到下一回合，也不会把传闻直接写成真实数据。
