## 3. 协议、兼容与恢复契约

### 分卷 v2

```
turn-data/v2/SHA256(campaignId)/SHA256(timelineId)/turn/
turn-data/v2/SHA256(campaignId)/SHA256(timelineId)/scenario.json
turn-data/v2/SHA256(campaignId)/SHA256(timelineId)/reference.txt
```

显示存档名仅用于 UI 和旧目录查找，不能作为写入身份。IPC 的读取、列举、摘要导出与删除需要 `{saveName, campaignId, timelineId}`，回合操作再附严格 turn，事务操作再附 transactionId/stateChecksum。preload 声明 `turnDataProtocolVersion: 2`。

同一世界/回合由第一个事务占有，不同事务不自动 replace。相同事务只有描述符和内容一致才能重复 stage/publish。stage 不等于世界已提交；原 canonical world + receipt 同一 IndexedDB 事务约束仍保留。恢复可完成已提交世界对应的分卷，不提前清 receipt。

旧 final/staging 的 transaction manifest 能证明 campaign/timeline/turn/transaction/checksum 才复制迁移；中断后重试，原件不删除。不带身份证明的旧目录、损坏资料及共享旧 scenario/reference 不按当前世界猜测归属。只迁移有事务归属的辅助文件。自动清理只删除明确 v2 世界；若有尚待发布的 stage 则拒绝清理，旧资料保留。

旧 renderer 写入口明确返回升级错误；新 renderer 遇旧桥接明确失败，不能降级到“存档名 + 回合号”写法。主进程/preload 的这些改动必须由后续壳层安装包交付，不能单发 renderer OTA 假定协议已到达。

### 工坊提交点

`journal → stage 复制和完整验证 → 保留旧目录/切换 → 原子 index(_transactionId) → 清理备份`。journal 在 stage 复制前写入，以便失败/中断后的残留可识别；只有原子 index 的 ID 与 journal 匹配才视为提交。

提交前失败恢复旧目录且原 index 字节不变；提交后备份清理失败返回 success + warning，下次访问再清理，绝不称“已回滚”。恢复失败保留 journal/backup。文件锁拒绝并发操作，不让两个进程交叉写共享 index；应用内同步事务依次执行，忙时调用方收到明确失败而非丢更新。

死亡 PID 锁可在串行恢复锁下回收。无法证明归属的锁、损坏 journal/index、恢复锁本身遗留会 fail closed，需要人工检查保留材料；不猜测并删除未知锁。此为安全恢复策略的明确边界，不宣称任意机器掉电点都能无人值守恢复。

### 保存、账号和网络

- 手动保存使用“最后接受的保存意图拥有 UI”语义；已经发出的 A detached 快照可以完成 A 自己的磁盘写入，但迟到结果不能修改 B。后续同局保存写盘串行。
- 账号“最后接受的认证/资料写意图”在请求发起时使旧请求失效，包括最后一次登录最终失败的情况。退出须先可靠删除本地 session；远程撤销失败明确标记未确认，不把它等同于远程 token 已撤销。
- 旧合法存档读取保持只读，存档名称不再通过 sanitize 寻找碰撞别名；hash 存储键、普通文件/路径限制保留。
- 固定 API/工坊目录、路由白名单、HTTPS、生产 IP literal 禁止、包 hash/签名、固定 Ed25519 key、可信 IPC 来源、秘密字段脱敏未放宽。
- 网络改为受控直连：不继承 Electron session 的 cookie/proxy，也不启用环境代理/共享连接。依赖企业代理的网络可能不再可达，需要另行设计同等地址约束的代理策略；不会以回退未绑定解析的连接绕过保护。TLS/SNI/Host 保留遵循 Node HTTPS request 的 hostname/lookup/证书参数契约，未关闭 TLS 验证。
