## 一、已修复的问题

**自动档无回执。** 原代码会一直等待且一直占用在途标记。现在默认 60 秒后结束本地等待，报告 DESKTOP_AUTOSAVE_UNCONFIRMED。原生写入未返回前仍保留单个在途保护，同一页面不会再发另一笔自动档去覆盖或排队竞争。超时不表示远端已取消，更不表示已保存。

**迟到回执。** 晚到成功或拒绝只释放原生请求保护并记录阶段，不补写成功时钟、已保存回合或轻量镜像。后续明确调用可以在保护释放后保存最新快照。主进程始终不返回时，本页仍拒绝重复写入，不能声称已经解决底层磁盘卡死。

**preload 会话倒退。** 请求捕获自身会话和轮换代次，回执不再作为无条件轮换依据。切档后返回的旧成功或旧失败不得把当前会话令牌改回去；当前请求的成功回执若带有不匹配令牌，也不能推进保存状态。生产桥接的 API 字段没有增加，主进程的串行临时文件与 rename 校验保持原样。

**发送前的异步空隙。** 排入微任务之后、真正发送之前再核对世界、加载代次、桥接实例和已提交快照；文本序列化后再核对一次。防止旧快照在切档之后带着新会话被发送。调用返回后继续检查这些身份，不把旧写入计成新世界的闲置保存基线。

**同回合的新快照。** 闲置跳存除了回合号，还核对已提交快照的修订计数。同一回合里，后台记忆等内容已经形成新快照时仍应保存；完整快照没有变化时继续跳过重复写盘。计数不进入游戏世界数据，不增加一份大世界缓存。

**关闭前检查。** 本地等待已经结束但原生写入结果未确认时，关闭前协调器不能宣称保存队列已经排空。旧世界的成功回执也不能满足当前世界的关闭检查。未确认写入只影响桌面恢复镜像的等待保护；主存档提交链没有被改成失败或减少内容。

## 二、质量与兼容性

正常路径保留既有已提交快照、文本桥接与旧对象桥接。文本序列化失败不会转用对象接口再写一次。成功时钟只在真实业务成功、身份仍匹配之后更新，明确失败可以按原流程再操作。

主进程完整源码、分卷提交器、普通 LLM/Agent 主推演、回合质量门槛、管道、原子主存档、压缩与快照等文件保持开工哈希；统一存档构造、快照筛选、项目外壳、后台保存协调、会话轮换入口等函数进行了逐函数对照。具体列表见 verification.json。

诊断入口 `_tmDesktopAutoSaveTransportStatus()` 返回在途/超时状态及最多十二条阶段记录，不返回存档正文、存档名或会话令牌，也不允许通过返回值修改内部状态。诊断只在当前页面内存保留。

## 四、交付范围与限制

这次包含生产 preload 改动，但没有重新打包桌面客户端，也没有提交或发布。仅替换网页资源不能据此认为已安装客户端的 preload 自动升级。主进程自动档的串行队列、文件提交协议和权限没有重写。

如果原生写入永远不返回，同一页面会持续保护该未知状态，不能强制解除后重发。主进程底层 I/O 的取消、跨进程重启自动对账、跨刷新响应恢复以及其他旧 IPC 接口，并未在本轮全部解决。60 秒是异步本地等待期限，系统挂起或同步阻塞时定时器也可能延迟。

未测量实际玩家整体过回合速度或成功率。本批收益是减少错误会话、漏存新快照、无限本地等待和关闭时的假成功，不通过缩减推演内容获取速度。
