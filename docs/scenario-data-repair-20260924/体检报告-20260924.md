# 三部官方剧本数据体检（2026-09-24）

- 基线：origin/main = `ea6ca883`，剧本真源 `scenarios/*（官方）.json`（三份都是单行 JSON：天启 16MB、绍宋 91MB、晚唐 66MB）。
- 性质：只读体检，没有改动任何剧本或代码。
- 工具（本目录，可重跑）：
  - `field-paths.js`：把三部剧本的每个字段按结构位置归类计数。
  - `field-usage.js`：把每个字段名和运行时代码（web 下 634 个游戏与编辑器脚本，不含测试与生成物）逐一对账，找出没有任何代码读取的字段。
  - `integrity.js`：引用完整性（势力、人物、地块、行政树、官制、军队、党派、阶层、关系）与数值、格式、文字体检，输出 `integrity-*.json`。
  - `dossier-dump.js`：在 VM 里真开局，调用正式方志渲染，导出玩家实际看到的文字（`dossier-tq/ss/tg/`）。
  - `runtime-facts.js`：开局后核对实体有没有丢、地块人口是不是随机兜底（`runtime-*.json`）。

## 一、结论

1. **天启府州数据是按系数平分出来的。** 五月 Codex 的脚本（地块上标着 `_codexGenerated: tianqi-prefectures-20260515`）把每省的数字按固定系数分给下辖府州：首府 1.29、普通府 1、州 0.83、镇 0.65。地形、物产、港口盐课等标签、民心吏治这些定性字段则整份照抄省级：382 个叶子区划里有 374 个和上级完全相同。描述是一句模板，382 个叶子没有一个写了主官名。省级那层真正手写的内容（巡抚、战略价值、士绅、书院、商路、灾异、威胁）在三级地图上没有页面能看到。
2. **天启还有一个开局就生效的坑。** 22 棵外藩行政树的键名（`laterJin`、`tokugawaJapan`……）既不是势力 id 也不是势力名。`initProvinceEconomy` 按键名找势力，找不到就把整棵树跳过，这些地块改用 5 万到 10 万之间的随机人口。江户两次开局分别是 55,532 和 59,809，剧本里写的是 2,795,082。另外 55 个人物的 `factionId` 还是旧一代的 id（`fac_mp3yvbc…`），13 棵行政树上写的 `factionId` 也对不上现存势力（现存的是 `fac_mp9rsc3…` 和 `fac-…` 两种）。播州、郑氏、陕北饥民、奢安四家的 23 份原账不绑地块，这是 Codex 有意保留的「非领土账」，不算错。
3. **绍宋的数字基本不能用。** 人口分布像是随机的：扬州（建炎元年的行在）5,430 口、实征 578；威州 221 万，全宋第一；共城县 117 万；陈留县 25.8 万，比开封府 17.2 万还多。595 个府州的耕地是 2.36 这样的小数，量纲是错的。年龄、性别、族群、聚落用 `"34%"` 字符串加中文键，方志上显示成「幼 0 / 青壮 0 / 老 0」「男：0 / 女：0」。616 段地方描述是制作说明（「建炎元年八月地理与势力归属按绑定地图几何重新判定，当前由宋控制」），应天府、拱州也被写成「京畿路·东京开封府」。行政树没有路这一级，府州没有官职也没有主官。人物 id 有 9 组重复，开局按 id 去重，丢了 16 个人，其中有耶律大石。150 个党派只有 8 个进得了游戏，250 个阶层只有 16 个。
4. **晚唐的引用关系反而最干净，问题出在「造」。** 194 个字段名运行时代码一处都不读，在文件里一共出现 71,113 次（例如 `circuitTitle`、`localRepresentatives`、`fiscalNarrative`、`playRole`、九种 `…FiscalAssessment`）。另有一批是 Codex 顺手写了引擎去读的新账本（人口账 /2、财政账 /2、公帑 /2、人力），只有晚唐声明。434 个人物里 353 个是虚构的，其中 176 个「地方代表」按姓批量起名（范元简、范景简、范怀简、范敬安……），每人重复挂在 15 到 21 个州。神策左军长安营的统兵官是虚构的陆文远；右神策军 6 万人没有统兵官，而右神策军中尉鱼弘志就在人物表里。`population` 写成对象，地形写成英文 `plains`/`hills`，省道登记换了一套 `memberSeeds` 结构，44 个道只有 12 个有长官。

## 二、问题一：两级地块之后的数据缺失

### 2.1 天启府州（证据）

- **系数平分**：北直隶 11 个府州的权重依次是 0.1218（顺天）、0.0943（保定、河间、真定、大名、永平、顺德、广平）、0.0786（延庆、保安二州）、0.0613（宣府镇）。南直隶是应天 0.0914、其余 12 府各 0.0708、徐州 0.0590。所以苏州、松江、常州、镇江、扬州、淮安、凤阳、安庆、徽州、宁国、池州、太平的人口都是 1,168,142 口。
- **方志实测**（VM 里真开局后渲染，原文在 `dossier-tq/`）：
  - 苏州府与凤阳府除了驻军以外逐行相同：户口 117 万、实征 125 万、耕地 672 万、盐课 58.4 万、特殊资源「丝绸·棉布·茶·漕米·盐(两淮)」、标签「港口、盐课、渔课、皇庄」。
  - 宣府镇：地势「平原」，特殊资源「漕运·煤·铁·海盐(长芦)」，标签里有「港口」，海贸 1 万，主官「守备 空缺·待补」。
  - 西安府：民心 0（危），吏治 99（蠹）；陕西各府的民心、不稳全是省级那一个数。
- **定性字段照抄率**：地形 374/382、特产 374/382、标签 368/382、民心加吏治 374/382。
- **描述模板**：「北直隶地块内的府级要地，地形以平原为主，关联漕运、煤、铁。」同省各府只换「府、州、镇」一个字；外藩一律是「某某地块内的要地级要地」。
- **主官**：382 个叶子没有一个有主官名。泛称「知府」「知州」「守备」找不到唯一持有人，方志全部显示红字「空缺·待补」，整张地图看起来像是全国知府出缺。
- **外藩叶子**：江户的户数 55.9 万、丁数 117 万，口数却显示 5.6 万（就是上面说的随机兜底）；耕地 5 万亩，商贸却有 3421 万、海贸 1882 万。苦兀岛、黑龙江下游、虾夷诸地的耕地只有 39 到 98 亩。
- **省级手写内容看不到**：17 个省节点上有巡抚、战略价值、士绅、书院、商路、近年灾异、宗教场所、威胁、风俗，府州方志里没有这些，省道级目前也没有页面（通志页 S2 还没做）。

### 2.2 绍宋、晚唐的层级缺口

- **绍宋**：行政树没有路，277 个府州直接挂在「大宋」下面。地图的省道登记有 101 组（大宋 27 组），只有名字。府州没有 `officialPosition`、`governor`、`terrain`、`specialResources`，描述写在 `desc` 里。另外还有县、山寨、陉口被当成府州级地块（陈留县、杞县、尉氏县、共城县、五马山寨、太行陉……）。
- **晚唐**：44 个道里只有 12 个有长官（刘沔、李绅、李德裕、李石、牛僧孺、李固言、卢钧、马植、何进滔、王元逵、史元忠、刘从谏）。道节点在源数据里人口为 0，开局时引擎会从叶子汇总补上，这点不算错。府州级缺 `tags`、`specialResources`、`taxLevel`、`officialPosition`、`governor` 和年龄、性别等结构，Codex 的说明是「未核实所以不写」。

说明：「零引用」指这个字段名在 634 个运行时脚本里一次都没有出现。它不影响推演（主要提示词构造器不整包序列化人物和区划），但占体积，也会误导后来写剧本的人（包括 AI）。

附带发现：三部剧本都把地图存了两遍（`map` 与 `mapData` 内容逐字节相同），天启 16MB 里有 13MB、绍宋 91MB 里有 82MB、晚唐 66MB 里有 51MB 是地图的两份拷贝。这属于后续性能优化的范围。

## 五、修复方案（建议）

**阶段零：定宪法，立闸门，修两处引擎。**
1. 写一份区划数据宪法：省道节点放叙事与长官，数字一律由下辖府州实时汇总（与通志计划的铁律一致）；府州节点的必备字段、类型和取值口径以运行时实际读取为准。
2. 把本次体检脚本改成仓库里的 `lint-scenario-data`：死字段、格式错、引用断、数值越界、模板描述都报错。先只出报告，三部修完再接进 CI，以后不论谁（包括 Codex、GPT）改剧本都过不了闸。
3. 两处与朝代无关的引擎修复：`initProvinceEconomy` 先按行政树上声明的 `factionName`/`factionId` 找势力，键名只作兜底；泛称官职（知府、知州）没有持有人时显示「任官未详」而不是红字出缺（晚唐已有 `occupancyStatus:'unrecorded'` 这条路，可推广）。

**阶段一：天启府州重写**（同志说最严重，先做）。先拿南直隶 14 个府州做样板回桌，再铺开。

**阶段二：绍宋修复。** 重建人口、田亩、税额；格式归一；重写 616 段描述；补路一级（安抚使、转运使）和府州官职；修 id 重复找回 16 人；理顺势力、党派、阶层引用。

**阶段三：晚唐清理。** 删死字段（有用内容并进正规字段）；`population`、地形、省道登记格式归一；修挂错的人，补缺位长官；处理批量虚构人物。

**工作方式：**
- 剧本是单行大 JSON，git diff 看不了。每一刀用可重跑的补丁脚本改真源，同时生成字段级变更报告给同志看；派生物用 `sync-official-scenarios.js` 重生成。
- 读官方剧本的脚本有 84 个，每刀按主题回归，改到数值断言的要逐条对账。
- 另开 worktree 基于 origin/main；主库和 D 盘几个 Codex worktree 里有未提交的天启 JSON 改动（相对旧分支），不碰。
- 通志页（S2）照原计划做，它负责把省级手写内容显示出来；本计划负责把府州数据本身修对，两条线互相补。
