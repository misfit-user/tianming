## 真实接线

正式加载在原 `OfficeHolderState`、`NpcBehaviorRegistry` 和 `ActionLedger` 后增加 `tm-political-actions.js`。它是身份、知情与领域提交适配器，没有另一份世界、账户、外交队列或条约库。

```text
本地模板 / SC16 / 势力 LLM 或工具
  → 当前真实人物、组织、行事职任与可信来源
  → 本人实际知识、候选与独立选择
  → 原 ActionLedger 的延期事项
  → 正式 endturn apply.writeBack 安全点
  → 当前权限、资源、条款、world lease 复核
  → 现有领域写口 + 同一短事务
  → 本次操作凭据、实际阶段、来源相同的经历与报告
  → 原保存生命周期
```

- **职任**：只读解析 `GM.officeTree`、`fac.officeTree` 与启用的 NativeWorld 任职真源；不临时替换 GM。任命／免职／转任仍由原 office mutator 完成并回读岗位。显式错误 ID、同名、另一局对象不会退回任意名字。代理、兼任、授权到期和同回合改革立即复核。
- **公库**：`PublicTreasury.transfer` 是唯一扣入账写口；岗位保管范围、支用权、可用额、额度分别检查。回执核对本次流水、账户、金额及前后账。普通 `treasuryDelta` 候选不产生财富；NativeFiscal、CascadeTax 与 legacy 正常周期保留，legacy 同周期重入只结一次。
- **外交**：原 `_incomingProposals` 保存草案、版本、送达、回应、表决、签署及未履行义务。两方当前条款均有效同意后，原 `TreatySystem` 写唯一 `GM.treaties`；兼容现有字段和战争消费者。普通联络人、谈判代表、最终签署人、集体议事有不同权限。合法单方退约仍能执行。
- **人类选择**：原使节批准／还价按钮及历史事件提案进入可信 `executeHuman`；NPC 不替玩家同意。整国 `isPlayer` 不再冻结有权的其他 NPC；旧财政结算所有者划分保留。
- **军令／战争**：军令复用 `CommandAuthority` 与掌兵者回执，开拔进入 `MarchSystem`，不直接跳地点或凭命令增加兵员。宣战与参战继续经过原 CasusBelli 和战争门槛，已有战争不能证明新动作完成。
- **生成／时间**：eager、in-turn、idle、manual 共享预算与身份租约。只生成不计执行；真实等待不增加模拟收益。决定时见到的提案版本和条款随 packet 保存，后来送达的秘密不能追认旧候选。
- **文书／策略**：本地模板进原 `_npcPlans` 候选，人物可采纳、拒绝、暂缓；文书走上一轮双向行动链。SC16 只取公开事实并给可选择建议，不直接改变组织关系，不以 must_follow 代替人物选择。

已退役独立引擎没有恢复。渲染岗位、右栏读任职改为只读；开始／恢复时的显式初始化继续存在。没有改变入口名称或制作平民界面。

## 正向流程证据

### 双边协议与实际战争消费者

`smoke-political-action-unification.js` 从普通联络人的长条款建议开始：本国代表实际收到并接手，对方收到后还价到第 2 版；第 1 版回应被拒，第 2 版获双方有效决定后生成一条联盟。随后第三国进攻，现有 `CasusBelliSystem` 确实识别联盟并让盟方参战。原玩家使节批准分支另测：未送达不知情、未选择不接受、重复点击不重复签约或再加旧效果。

`smoke-political-official-scenarios.js` 加载三份完整 canonical 剧本数据，走提案、在途 JSON 保存恢复、送达、代表或集体选择、原条约写入和 `hasTreaty` 消费；三者都得到唯一互不侵犯协议。绍宋使用具名原议事席的独立表决，不虚构缺席人物。

### 真授职、库存转移与继续办理

合成世界中，乙国代表从势力入口向乙国真实空缺授职；人物入口转述同一 actionId 只读取既有完成回执，经历不重复。NativeWorld 双组织夹具也实际写两国各自任职真源，玩家树保持为空。绍宋官方数据另有真实空缺授职回读。

公共账户夹具从甲库向乙库实际转 60；另一来源再申请 60 时库存不足而受阻，两个库总额不变。晚唐官方完整数据从魏州库向博州库转移 1，扣／入账守恒。物资条款接受后仍为未履行，只有实际付款人知情并作出当前有权决定，才能扣入实体账户并核销原义务。

原天启人物文书另走本地事项发现、提出协办、对方回应、交付核查文书、发起者反馈；未完成缺项继续保留原事项。实际主写回和 `_buildSaveState/_restoreSavedFields` 都有完整模块回归，官方大世界测试中的在途保存采用 JSON 序列化，二者证据不混称。

## 存档、兼容与回退

迁移先沿上一轮 ActionLedger 处理旧自报完成，再在现有事务里升级政治来源／提案。可重跑；失败回滚，不重播钱财、职位或历史奖励。旧有效条约保留，缺历史决定者标 `legacy_unattributed`；旧待办保留原 ID，缺完整决定依据时重拟。未知兼容字段保留。

组织义务不随签发人死亡自动消失；已签发在途文书保留当时事实，尚未签的新决定复核当前身份。既有私人经历不被接任者继承或因失官清空。活跃条约和事项不按展示上限删除。

三官方本次实际走 legacy 任职／财政；晚唐实体公库保留其 CascadeTax 分工。天启只补原具名外交席；绍宋三票集体规则明确标为模拟配置；晚唐只补有限外交、本府书吏任用与同组织库存移交。没有给全体官员万能权，没有新增钱粮。合成测试另覆盖启用 NativeWorld 的双组织任职；不声称官方测试已经验证全部原生公共账户组合。

新存档依赖本轮回执与提案版本语义。关闭精细推演只停止新模型候选，正常领域过程继续；缺依赖不会恢复旧直接差额写口。回退旧代码应恢复升级前存档副本，不能仅关一个开关继续写新语义存档。

## 明确未完成与未验范围

- `province_policy`、`rebellion_policy`、阴谋 pressure 的旧裁定未完成统一；只切断阴谋借道直接外交写入。
- 原势力 LLM 的 `raw.builds`、自动 repair 和 `goalUpdates` 尚未接当前人物授权／预算适配。新 decideFor 不调用其无依据财产差额；已有建筑世界过程保留，但这部分自动规划能力尚待恢复。
- 全部旧历史事件 `factionDelivery` 尚未逐个升级为有类型义务和实际付款人的决定；缺失材料明确受阻。通用贸易、通牒实物效果不在本轮完成范围。
- 其他 Agent 专家、全知世界结算及旧对话没有全游戏限知保证。本轮所改人物、势力 prompt/tools、SC16 投影及外交检索有实际秘密标记测试。
- 没有运行真实模型、完整浏览器交互、移动端或生产玩家存档验收；离线正式模块入口不能替代这些验收。
- 当前成果是任务最小范围及已列领域的实现，不是全部政治动作或全部模式已经统一。
