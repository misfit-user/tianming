## 职任与私人外出

### 已有规则不会被调用参数取消

外出检查读取当前人物的实际任职和有效的现场代办。`actorOfficeConstraint`、`targetOfficeConstraint` 只能引用实际职任；`requiresLeave:false` 不改变真源。兼任逐项核对，许可不跨人物、组织或任职借用。组织沿现有 `PoliticalActions.resolve` 查验，不能仅凭一个非空字符串认定存在。不存在或重复的组织 ID 无法提供本次外出依据。不同有效组织可以有相同岗位 ID；同一组织内岗位 ID 不唯一则不能确定本次约束。

最终审查另复现同一类直接缺口：明确配置驻任职责却缺少岗位 ID 时，旧读口仍返回已解析，旅行层跳过该行，实际无许可启程；虚构组织或重复组织 ID 的常设规则记录也能被旧代码用于启程。当前补丁将明确配置的空岗位 ID、空组织、组织解析失败和不唯一复合身份返回未知；已生效代理的岗位身份缺失也不再消除其现场责任。证据见 `m1-missing-identity-reproduction.json`，复跑入口为 `reproduce-m1-identity.cjs`。该证据加载旧生产源码执行真实邀请与接受，不靠新函数不存在制造失败。有效组织的常设规则正向仍可出发。

### `legacy_unspecified` 是未配置制度的兼容状态

只有完全没有 `officeTenure`、`tenure`、`dutyRules`、`dutyConfig` 的岗位进入此状态。它保留旧剧本的私人活动能力，不凭官名补造历史假制，也不证明该官员具有一张已经批准的假期。

同一人物另有明确配置的职责，仍须核对那项职责。明确配置后缺驻地、日期或身份，属于未知或不完整，不能降为 `legacy_unspecified`。查询失败和必要模块缺失同样不能当成无职。

官方兼容测试中的天启旧岗位仍有此状态。它不能作为“正式驻任官员已经走完申请、批准、外出及归任 UI”的证据。要验收具体岗位制度，需在实际配置中明确地点与规则，并通过对应可信操作形成许可。

### 外勤有合法正向，也有明确边界

当前生产模块测试包含：

- `field` 职任取得真实私人外出许可后能够出发。
- 位于允许辖区内的私人外出仍核许可；到场后不会因当前位置改变而洗掉原行程责任。
- 该合法分支可以实际参加并返回任所。
- 当前职责地点内的私人会面无需伪造远行许可。
- `_officeFieldDuty=true` 本身不能批准私人远行。
- `field_duty` 差遣许可不能改充 `private` 许可；私人赴约许可也不赋予目的地公权。

本轮没有重写巡历、奉差和全部公权 `canAct` 语义，也没有承诺每一种历史外勤配置已完整验收。当前许可使用明确目的地和返任地点；没有新增任意目的地区域表达式、多站差旅规则或无限期停留制度。

### 尚未接管的职任范围

- 全部官职与时代的假制、完整当值表、所有公务冲突规则未重制。
- 有效现场代理不能仅靠私人邀请自行离开；超出已有解除或交接接口的替换安排未新增。
- 旧许可缺少新任职身份时，不自动绑定到新任职；已发生历史保留，不倒改为新的许可。
- 本次组织身份修复作用于私人外出依据；没有重写所有旧许可记录的生成和所有公权接口。旧记录存在不等于当前可执行，也不在读口批量清洗或授予许可。
- 本轮核对已实现的离任交代和有限代理，不宣称全部代理 UI、全部归任报告界面已验收。
