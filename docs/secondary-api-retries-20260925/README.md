# 次要 API 失败重试设置

设置入口：游戏设置 → 性能·成本与预算 → 次要 API 重试 → **次要 API 失败后重试次数**。

默认失败后重试 1 次，即最多发送 2 次。玩家可填写 0–20，0 关闭自动重试，留空或点击“恢复默认（1 次）”恢复默认值，点击“全部保存”后生效。关闭面板不会提交草稿；重启、异步读取旧项目及切换旧存档会保留已保存的选择。

## 策略

- 显式的过回合单项／基础 ID 设置优先；否则实际使用次要 API 的游戏生成调用采用新设置。主要 API 继续使用原有策略。未启用或未配置次要 API 时，不套用次要设置。
- 普通、消息、智能、流式和工具请求共用已解析的重试次数。网络不可达时切主 API 使用剩余额度，不另加一套主 API 默认重试。
- 设置对正在进行的请求不追溯扩容。取消、切档、明确期限、鉴权失败、未确认的原生发送、已经产生的部分流式输出保留现有停止边界。
- 常朝、独召、NPC 决策及人物生成的业务外层，在底层请求耗尽后不再整轮重开；合法的格式修复和原有模板降级保持各自职责。
- 模型连接、首包测速及能力探测属于独立诊断流程，保留原测量口径；紧急修复与整回合复核仍由其明确的一次性请求及总预算管理。

字段：`P.conf.aiSecondaryRetryCount`。未保存的新旧项目均通过策略默认值读取为 1，无需改写存档来迁移。
